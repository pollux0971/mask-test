## Story

**As a** 開發者
**I want** 最簡單的距離度量先跑通
**so that** 我有一個基準來評估 DTW 到底帶來多少提升

## 為什麼是這個順序

沒有基準就無法評估改進。如果餘弦已經 75%，而 DTW 只到 78%，那 DTW 的複雜度可能不值得。**這個數字要先量出來。**

## 範圍

**包含**
- 固定長度序列攤平後的餘弦距離
- per-modality 版本（只用 ToF 或只用 Mel）
- 批次計算（一個 query 對 N 個樣板）

**不包含**（避免範圍蔓延）
- DTW（D05）
- 分數轉換（D06）

## 實作

```python
def cosine_dist(a, b):          # a, b: (T, D) → 純量
    x, y = a.ravel(), b.ravel()
    return 1 - (x @ y) / (np.linalg.norm(x) * np.linalg.norm(y) + 1e-12)
```

批次版本用矩陣運算，一次算完所有樣板（8 詞 × 8 樣板 = 64 個，攤平後是 64 × 2496 的矩陣乘法，< 1 ms）。

**這個 story 完成的當下，你就有一個能跑的辨識器了。** 即使 D05–D09 都還沒做，你可以先用它跑 LOOCV 看看資料到底可不可分——這個早期訊號很有價值。
