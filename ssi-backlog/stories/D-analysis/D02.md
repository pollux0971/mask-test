# D02 — 音訊特徵：CMN 與長度正規化

| 欄位 | 值 |
|---|---|
| **軌道** | D 分析引擎 |
| **Epic** | E3 特徵 |
| **估時** | 2 h |
| **前置** | `T03`, `B14` |
| **阻擋** | `D03`, `D13` |
| **需要硬體** | 否 |
| **可平行於** | A/B/C 軌全部 |

## Story

**As a** 辨識引擎
**I want** 消除通道效應與音量差異的 Mel 特徵
**so that** 同一個詞在不同音量、不同接觸鬆緊下仍能比對

## 為什麼是這個順序

骨傳導麥克風的接觸鬆緊會直接改變頻譜的整體形狀（像換了一支麥克風）。倒頻譜均值正規化（CMN）就是為了消除這種通道效應。

## 範圍

**包含**
- CMN：減去該 utterance 的 per-band 均值
- 可選的 CVN（除以標準差）
- VAD 區間裁切（用 B15/B16 的邊界）
- 與 A12 裝置端輸出的一致性檢查工具

**不包含**（避免範圍蔓延）
- MFCC 轉換（先用 log-Mel 即可，DCT 可選）

## 實作

```python
def mel_features(mel, vad_start, vad_end, cvn=False):
    m = mel[vad_start:vad_end]
    m = m - m.mean(axis=0, keepdims=True)       # CMN
    if cvn:
        m = m / np.maximum(m.std(axis=0, keepdims=True), 1e-6)
    return m
```

**CMN 對 utterance 內做，不是對整個 session 做。** 對 session 做會保留 utterance 之間的通道差異——那正是我們要消除的。

要不要做 DCT 轉成 MFCC？**建議先不做。** log-Mel 已經可用，DCT 會增加一個超參數（保留幾維）而收益不確定。等 D05 的 DTW 跑出基準之後，再實驗 MFCC 是否更好——這是一個明確的 A/B 比較，而不是一開始就猜。

## 驗收條件

- [ ] CMN 後各 band 的均值接近 0
- [ ] 同一個詞不同音量錄兩次，CMN 後的 DTW 距離明顯縮小
- [ ] 與 A12 裝置端輸出的相關係數 > 0.95（A12 完成後執行）
