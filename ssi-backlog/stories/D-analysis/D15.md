# D15 — 驗證報告產生器

| 欄位 | 值 |
|---|---|
| **軌道** | D 分析引擎 |
| **Epic** | E5 物理驗證 |
| **估時** | 2.5 h |
| **前置** | `D10`, `D11`, `D12`, `D13`, `D14` |
| **阻擋** | `C22`, `C23` |
| **需要硬體** | 否 |
| **可平行於** | A/B/C 軌全部 |

## Story

**As a** 研究者
**I want** 一個指令跑完全部驗證並產出報告
**so that** 每次改硬體或戴法後能快速重跑

## 為什麼是這個順序

調整骨架之後你會想知道「SNR 有沒有變好」。如果重跑要手動執行五個腳本再自己拼結果，你就不會常常做——而快速迭代正是這個階段最需要的。

## 範圍

**包含**
- `python -m analysis.run_all --session <file.h5>`
- 產出 `summary.md`（通過矩陣置頂）+ 各實驗的 md + figures/
- 同時輸出 HTML 版供 C23 檢視
- 必通過項目失敗時 summary 頂端紅色警示

**不包含**（避免範圍蔓延）
- 圖表樣式（D20）

## 實作

`summary.md` 開頭就是這張表：

| 實驗 | 指標 | 實測 | 標準 | 判定 |
|---|---|---|---|---|
| C₀ | Δ_dist | 1.3 mm | < 2 mm | ✓ PASS |
| A | SNR_L / SNR_R | 4.2 / 3.8 | > 3 | ✓ PASS |
| B | CV_ToF | 24% | < 30% | ✓ PASS |
| C | Silhouette | 0.11 | > 0.15 | ✗ **FAIL** |
| E | Viseme 模式 | — | 有模式 | ✓ PASS |

**這張表是你每天最常看的東西**，所以要置頂、要能一眼掃完。

執行時間目標 < 2 分鐘。若 D05 的 DTW 讓 D13 變慢，加一個 `--fast` 用餘弦跑。
