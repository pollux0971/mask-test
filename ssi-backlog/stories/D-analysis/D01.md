# D01 — ToF 特徵：z-score 與活躍 zone 篩選

| 欄位 | 值 |
|---|---|
| **軌道** | D 分析引擎 |
| **Epic** | E3 特徵 |
| **估時** | 2.5 h |
| **前置** | `T02`, `T03` |
| **阻擋** | `D03`, `D10`, `D13` |
| **需要硬體** | 否（用 T02 的假 HDF5） |

## Story

**As a** 辨識引擎
**I want** 把原始 ToF 距離轉成正規化且去噪的特徵
**so that** 不同 zone 的雜訊水準差異不會淹沒真正的訊號

## 為什麼是這個順序

邊角 zone 通常沒有目標、雜訊大。直接把 32 個通道丟進 DTW，這些雜訊 zone 會貢獻大量無意義的距離。篩掉它們通常能明顯提升辨識率。

## 範圍

**包含**
- per-zone z-score，用 `/meta` 的 baseline μ / σ
- 活躍 zone 篩選：只保留 SNR > 門檻的 zone（門檻可設，預設 2）
- 無效 zone（`tof_valid_*` 為 False）的處理策略
- 回傳篩選後的 zone 索引，供視覺化與報告使用

**不包含**（避免範圍蔓延）
- 時間對齊（D03）
- SNR 計算本身（D11 提供）

## 實作

```python
def tof_features(tof, valid, baseline_mu, baseline_sigma, active_zones=None):
    z = (tof - baseline_mu) / np.maximum(baseline_sigma, 1e-3)
    z[~valid] = 0.0          # 無效 zone → 0（= 等於基線，中性）
    return z[:, active_zones] if active_zones is not None else z
```

**無效 zone 填 0（z-score 空間的基線）而非填距離的平均值。** 在 z 空間裡 0 就是「沒有變化」，這是最中性的假設。填其他值都會製造假訊號。

`np.maximum(sigma, 1e-3)` 的守衛不可省：某些 zone 在 baseline 期間可能完全穩定（σ ≈ 0），除下去會爆炸。

**活躍 zone 的篩選結果要輸出並記錄**——這本身就是研究發現。「32 個 zone 中只有 11 個對唇形有反應，且集中在嘴角區域」是一個可以寫進論文、也能指導下一版硬體設計的結論。

## 驗收條件

- [ ] z-score 後各 zone 的標準差接近 1（baseline 期間）
- [ ] 無效 zone 不產生假訊號（用人工注入的無效資料驗證）
- [ ] 活躍 zone 索引正確輸出
- [ ] σ ≈ 0 的 zone 不造成 NaN 或 inf
