# T02 — 凍結 HDF5 session schema

| 欄位 | 值 |
|---|---|
| **軌道** | T 契約層 |
| **Epic** | E2 資料集 |
| **估時** | 2 h |
| **前置** | 無（可立即開始） |
| **阻擋** | `B07`, `B17`, `D01`, `D10` |
| **需要硬體** | 否 |
| **可平行於** | T01, T03 |

## Story

**As a** B 軌（寫入端）與 D 軌（讀取端）
**I want** 一份凍結的 HDF5 結構規格
**so that** 分析程式可以在還沒有真實資料時就先對著 schema 開發

## 為什麼是這個順序

D 軌（分析引擎）的工作量最大、最耗時，但它不需要硬體——只需要知道資料長什麼樣。schema 凍結後 D 軌就能用假資料全速開發，這是把總工期壓短的關鍵。

## 範圍

**包含**
- group / dataset 階層與命名
- 每個 dataset 的 shape、dtype、單位
- 必填與選填的 attrs 清單
- `manifest.csv` 的欄位定義
- 版本欄位 `schema_version`

**不包含**（避免範圍蔓延）
- 實際的讀寫程式碼
- DVC 設定

## 實作

以 backlog 的結構為基礎，補上這些容易事後才發現漏掉的欄位：

```
/meta (attrs)
    schema_version, subject, session_date, wear_id, mode,
    distance_mm, angle_deg, ambient, notes,
    fw_sha, proto_version, tof_dim,
    clock_slope, clock_offset, clock_residual_p95    ← B04 產出
    baseline_mu (32,), baseline_sigma (32,)          ← 每顆感測器各一份

/trial_NNN
    tof_A       (T, 32) float32   # [0:16] 距離 mm, [16:32] signal/100
    tof_B       (T, 32) float32
    tof_t_us    (T,)    int64
    tof_valid_A (T, 16) bool      ← 別用 -1 混在數值裡，分析端很容易踩雷
    tof_valid_B (T, 16) bool
    mic_rms     (M,)    float32
    mic_peak    (M,)    int16
    mic_t_us    (M,)    int64
    mel         (M, 40) float32   # 選填
    audio       (N,)    int16     # 選填
    audio_t0_us          int64    # 錄音第一個 sample 的裝置時間
  (attrs)
    label, trial_idx, wear_id, mode,
    valid_zone_ratio, drop_count,
    vad_start_us, vad_end_us, lip_onset_us, voice_onset_us,
    quality {ok|low|rejected}
```

**`tof_valid_*` 用獨立布林陣列，不要把 `-1` 塞進數值裡。** 這是最容易在幾週後咬人的設計決定：`-1` 混在距離資料裡，任何一個忘記過濾的 `mean()` 都會靜默地產出錯誤結果，而且不會報錯。
