# T05 — Mock Device：真實 log 重播

| 欄位 | 值 |
|---|---|
| **軌道** | T 契約層 |
| **Epic** | E1 訊號地基 |
| **估時** | 2 h |
| **前置** | `T04`, `E01` |
| **阻擋** | `C05`, `C08` |
| **需要硬體** | 否（但需要一份已錄的 log） |
| **可平行於** | A 軌、D 軌 |

## Story

**As a** C 軌開發者
**I want** 把一段真實錄下的序列埠 log 逐行重播
**so that** 我調前端視覺化時看到的是真實訊號的樣子，而不是合成資料的理想波形

## 為什麼是這個順序

合成資料（T04）結構正確但太乾淨。等 E01 上機冒煙測試錄下第一段真實 log 之後，用它來調色階、調閾值、調動畫，前端才不會在 Demo 當天才發現「真實資料的動態範圍跟我調的完全不一樣」。

## 範圍

**包含**
- `--replay-log <file>` 逐行重播，依 `t_us` 還原節奏
- 速度控制：0.25× / 1× / 4×
- 循環播放

**不包含**（避免範圍蔓延）
- HDF5 session 的重播（那是 B17）

## 實作

最簡實作：`idf.py monitor` 的輸出直接 `tee` 存檔就是 log。

```bash
idf.py monitor | tee logs/raw_$(date +%Y%m%d_%H%M).log
python3 tools/mock_device.py --replay-log logs/raw_20260901_1430.log --speed 0.25
```

重播節奏用行內的 `t_us` 差值 `sleep`，不要用固定間隔——固定間隔會抹掉真實的抖動，而抖動正是 C09 品質儀表要顯示的東西。

## 驗收條件

- [ ] 重播的時序與原始 log 的 `t_us` 差值誤差 < 10 ms
- [ ] 0.25× 速度下可逐幀觀察熱力圖變化
- [ ] log 中的雜訊行（ESP_LOG 輸出）會被正確忽略
