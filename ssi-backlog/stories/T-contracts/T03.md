# T03 — 凍結特徵向量規格

| 欄位 | 值 |
|---|---|
| **軌道** | T 契約層 |
| **Epic** | E3 音訊特徵 |
| **估時** | 1.5 h |
| **前置** | 無（可立即開始） |
| **阻擋** | `A11`, `B14`, `D01`, `D02` |
| **需要硬體** | 否 |
| **可平行於** | T01, T02 |

## Story

**As a** A 軌（裝置端 Mel）與 D 軌（主機端特徵）
**I want** 一份明確的特徵定義
**so that** 兩邊算出來的 Mel 可以互相驗證，且辨識引擎的輸入維度固定

## 為什麼是這個順序

A12（裝置端 Mel）與 B14（主機端 MFCC）是同一件事的兩種實作。規格一致，兩者才能互為驗證與備援；規格不一致，切換路線時整個 D 軌要重做。

## 範圍

**包含**
- Mel 濾波器組參數：bands、頻率範圍、尺度公式
- 音框參數：窗長、hop、窗函數
- log 的底與 floor 值
- ToF 特徵的正規化方式
- 最終特徵向量的通道排列順序

**不包含**（避免範圍蔓延）
- DTW 或距離度量（D05 負責）
- zone 篩選門檻（D01 負責，此處只定義介面）

## 實作

```
音框     窗長 512 samples (32 ms) @ 16 kHz
         hop  256 samples (16 ms) → 62.5 Hz
         窗函數 Hann（週期性，非對稱）

Mel      n_mels    40
         fmin      80 Hz
         fmax      8000 Hz
         尺度      Slaney (mel = 2595 * log10(1 + f/700))
         濾波器    三角形，面積正規化
         log       log10(max(power, 1e-10))
         傳輸      裝置端 int16 = round(log_mel * 100)

ToF      通道 0-15   距離 mm
         通道 16-31  signal_per_spad / 100
         正規化      per-zone z-score，用 /meta 的 baseline_mu / baseline_sigma
         無效 zone   以該 zone 的 baseline_mu 填補，並在 mask 標記

特徵串接順序（104 維／幀）
         [ 0: 32]  tof_A
         [32: 64]  tof_B
         [64:104]  mel
```

**Slaney vs HTK 的 mel 公式差異要寫死在文件裡。** librosa 預設 Slaney、多數 C 實作用 HTK，兩者在 1 kHz 以上會有可見差距——A12 的驗收條件是「裝置端與 librosa 相關係數 > 0.95」，公式不一致就永遠達不到。
