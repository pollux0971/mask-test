# T06 — 專案骨架與軌道目錄劃分

| 欄位 | 值 |
|---|---|
| **軌道** | T 契約層 |
| **Epic** | — |
| **估時** | 1.5 h |
| **前置** | 無（可立即開始） |
| **阻擋** | `全部其他軌道` |
| **需要硬體** | 否 |
| **可平行於** | T01, T02, T03 |

## Story

**As a** 四條平行軌道
**I want** 一個事先劃分好檔案所有權的目錄結構
**so that** 平行開發時不會兩條軌道改到同一個檔案

## 為什麼是這個順序

平行開發最常見的失敗不是技術問題，是 merge conflict。事先劃清「哪個目錄屬於哪條軌道」，衝突就從結構上被消除了。

## 範圍

**包含**
- 建立目錄結構與 `__init__.py`
- `requirements.txt` / `pyproject.toml`
- `.gitignore`（排除 `build/`、`data/`、`voice/`）
- `CONTRACTS.md` 空骨架
- 每個目錄一個 `OWNER.md` 標明所屬軌道

**不包含**（避免範圍蔓延）
- CI 設定
- Docker

## 實作

```
esp-mask-test/
├── CONTRACTS.md              ← 共用，改動需通知全體
├── vl53l7cx_test/
│   ├── main/                 ← 【A 軌獨佔】韌體
│   └── monitor/
│       ├── bridge_server.py  ← 【B 軌獨佔】
│       └── panel/            ← 【C 軌獨佔】新的多檔前端
├── host/                     ← 【B 軌獨佔】
│   ├── capture/              trial 狀態機、VAD
│   ├── storage/              HDF5 writer、manifest
│   └── clock/                時鐘對齊
├── analysis/                 ← 【D 軌獨佔】
│   ├── features/
│   ├── similarity/
│   ├── experiments/
│   └── reporting/
├── tools/                    ← 【T 軌】mock device
├── config/
│   ├── vocab.json            ← 共用，C 軌與 D 軌都讀
│   └── quality_thresholds.json
├── data/sessions/            ← gitignore
├── templates/                ← enrollment 樣板，gitignore
└── reports/                  ← 產出，gitignore
```

**`config/` 是唯一的共用可寫目錄。** 它裡面只放純資料（詞彙集、閾值），不放程式碼，所以就算兩軌同時改也是簡單的 JSON 合併。

`panel.html` 拆成 `panel/` 多檔是 C01 的工作，這裡只先建目錄。
