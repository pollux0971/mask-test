# C11 — 錄製模式：session 設定表單

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E2 資料集 |
| **估時** | 2 h |
| **前置** | `C03`, `B09`, `B10` |
| **阻擋** | `C12` |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** 資料蒐集者
**I want** 開始 session 前填寫戴法與環境參數
**so that** 跨 session 差異出現時我知道要怪哪個變因

## 為什麼是這個順序

metadata 是事後無法補的。當你發現第 3 個 session 的資料特別好，卻不知道那天的戴法距離是多少，那個發現就浪費了。

## 範圍

**包含**
- 六個必填欄位的表單（subject / wear_id / mode / distance_mm / angle_deg / ambient）
- 上次設定預填，`wear_id` 自動 +1 但可改
- 送出後自動進入 30 秒 baseline 擷取畫面（含倒數與穩定度即時顯示）
- baseline 不穩時顯示哪些 zone 有問題並提供重錄

**不包含**（避免範圍蔓延）
- 後端驗證（B09）
- baseline 計算（B10）

## 實作

**`wear_id` 的 UI 要特別設計**：它預設 +1（因為通常是重新戴上），但有時是同一次戴上繼續錄。做成一個明顯的切換：「🔄 重新戴上（wear_id → 4）」vs「➡ 同次繼續（wear_id = 3）」。

實驗 B（D12）完全依賴這個欄位區分「同次戴 CV」與「跨次戴 CV」，填錯會讓整個實驗失去意義，所以值得為它多花 UI 心力。

baseline 擷取畫面要顯示即時的穩定度——受試者看得到自己有沒有在動，會自然地保持不動。
