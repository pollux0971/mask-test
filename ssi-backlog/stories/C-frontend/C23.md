## Story

**As a** 研究者
**I want** 在 UI 裡直接看報告與圖表
**so that** 我不用切到檔案總管找 PNG

## 為什麼是這個順序

實驗跑完立刻看到熱力圖，才能當下判斷要不要調整戴法重跑。開檔案總管找圖這個動作會讓「跑實驗 → 看結果 → 調整 → 再跑」的迴圈變慢。

## 範圍

**包含**
- 列出 `reports/` 下的所有報告，依日期排序
- Markdown 渲染 + 圖片內嵌
- 通過矩陣總表置頂
- 可比較兩份報告（並排）

**不包含**（避免範圍蔓延）
- 報告產生（D15）

## 實作

Markdown 渲染用一個輕量的解析器（或直接讓 D15 同時輸出 HTML 版本——更簡單，維持零建置）。

**「比較兩份報告」是這個 story 的價值所在**：調整骨架前後、不同 wear_id、不同 mode 的結果並排，差異才看得出來。純看單一報告很難判斷 SNR 3.2 是好還是壞。

通過矩陣置頂：一眼看出五個實驗現在的狀態，這是你每天最常看的一張表。
