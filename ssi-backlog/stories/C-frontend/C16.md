# C16 — 測驗模式：三軌評分長條圖

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E6 閉集合 Demo |
| **估時** | 3 h |
| **前置** | `C15`, `D07` |
| **阻擋** | `C17`, `C18` |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** Demo 觀眾與口試委員
**I want** 同時看到「只用 ToF」「只用音訊」「融合」三組分數
**so that** 我能判斷這個裝置到底是不是真的在讀唇

## 為什麼是這個順序

**這是整個 Demo 最重要的一個 story。沒有它，你的 Demo 和一支麥克風沒有區別。** 少了 sEMG 之後，剩下兩個模態裡有一個是麥克風，而麥克風本身就能做語音辨識。如果準確率 90% 卻全是麥克風貢獻的，你證明的是「麥克風可以聽聲音」。

## 範圍

**包含**
- 三欄並排，每欄 8 條長條依分數排序
- 分數變動時動畫重排（0.3 s ease-out）
- 每軌獨立標示自己的 top-1 與信心度
- 三軌 top-1 不一致時，視覺上突顯這個分歧

**不包含**（避免範圍蔓延）
- 權重滑桿（C17）
- 混淆矩陣（C20）

## 實作

```
┌─────────────┬─────────────┬──────────────────┐
│  ToF only   │  Mel only   │  Fused  ★        │
│  五 ████ 71%│  五 ██ 42%  │  五 █████ 83%    │
│  一 ██  22% │  四 ██ 31%  │  一 █    9%      │
│  ...        │  ...        │  ...             │
└─────────────┴─────────────┴──────────────────┘
```

**三軌 top-1 不一致時要突顯**，因為那是最有資訊量的時刻：ToF 說「五」、音訊說「四」、融合說「五」——這一眼就展示了融合在做什麼。用一條連線或高亮框標示。

動畫重排用 FLIP 技巧（記錄舊位置 → 改 DOM → 算差值 → transform 動畫）。0.3 s 是刻意的：太快看不清誰超過誰，太慢會讓 Demo 拖沓。

側邊欄摺疊（C02）在這個模式特別有用——三欄需要橫向空間。
