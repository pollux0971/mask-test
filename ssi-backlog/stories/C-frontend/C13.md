# C13 — 錄製模式：進度與 trial 清單

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E2 資料集 |
| **估時** | 2 h |
| **前置** | `C12` |
| **阻擋** | `C14` |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** 資料蒐集者
**I want** 隨時看到進度、各詞的樣本數、以及剛錄的那幾筆品質
**so that** 我知道還要多久、哪個詞還缺樣本

## 為什麼是這個順序

錄 72 筆要 5 分鐘，中間沒有進度回饋會覺得很漫長；而且如果某個詞一直錄壞，你會想在當下就補錄而不是全部錄完才發現。

## 範圍

**包含**
- 進度條 + 「第 n / N 筆」+ 預估剩餘時間
- 各 label 的已錄數量長條（一眼看出哪個缺）
- 最近 10 筆的縮圖清單（label + 品質燈號 + 幀數）
- 點擊某筆可預覽其 ToF Δ 熱力圖與波形

**不包含**（避免範圍蔓延）
- 重錄（C14）

## 實作

「各 label 已錄數量」的長條圖比純進度條有用：Enrollment 需要每個詞都有 8 筆，如果隨機打散導致某個詞落後，這張圖立刻看得出來。

**最近 10 筆的品質燈號**用 B19 在 trial 存檔時附的 `quality` 欄位。連續兩三筆都是黃燈就是明確訊號：戴法在跑掉，該停下來調整了。

預估剩餘時間用實際的平均 trial 耗時算，不要用理論值——實際會因為休息、重錄而更久。
