# C15 — 測驗模式：8 選項題目版面

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E6 閉集合 Demo |
| **估時** | 2.5 h |
| **前置** | `C03`, `B13` |
| **阻擋** | `C16`, `C18` |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** Demo 觀眾
**I want** 螢幕上清楚顯示 8 個候選選項
**so that** 我知道系統的候選範圍，也知道它不是在做開放式辨識

## 為什麼是這個順序

這是你指定的核心需求。閉集合的「集合」必須讓觀眾看見——否則辨識成功時觀眾不知道那有多難（8 選 1 的隨機基準是 12.5%，這個脈絡要給）。

## 範圍

**包含**
- 8 張選項卡片，由 `config/vocab.json` 驅動
- 每張卡片顯示：詞、viseme 類別、預期主要模態
- reject 指示（第 9 個位置，樣式不同）
- 「請念出其中一個」的提示與 Auto-VAD 就緒狀態
- 隨機基準 12.5% 常駐顯示

**不包含**（避免範圍蔓延）
- 評分顯示（C16）
- 結果卡（C18）

## 實作

`config/vocab.json`（T06 規劃的共用設定）：

```json
{"words": [
  {"id":"ba",  "text":"八",   "viseme":"A 雙唇", "expect":"ToF"},
  {"id":"wu",  "text":"五",   "viseme":"B 圓唇", "expect":"ToF"},
  {"id":"yi",  "text":"一",   "viseme":"C 展唇", "expect":"ToF"},
  {"id":"a",   "text":"啊",   "viseme":"D 開口", "expect":"雙模態"},
  {"id":"si",  "text":"四",   "viseme":"F 擦音", "expect":"音訊"},
  {"id":"hao", "text":"好",   "viseme":"G 應用", "expect":"雙模態"},
  {"id":"ting","text":"停",   "viseme":"G 應用", "expect":"雙模態"},
  {"id":"buyao","text":"不要","viseme":"G 應用", "expect":"ToF"}
], "reject": {"id":"_reject","text":"靜止/其他"}}
```

**顯示 viseme 類別與預期模態是刻意的教育設計。** 觀眾看到「四 — 擦音 — 預期音訊」，就理解為什麼待會純 ToF 模式下它會認不出來——這讓 Demo 腳本第四步的「主動展示失敗」變成一個預期中的、有解釋的現象，而不是意外。

詞彙集由設定檔驅動，所以 E08 的「降到 4 選項」備援只需要改一個 JSON。
