# C25 — 設計 token 與跨模式視覺一致性

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E4 儀表板 |
| **估時** | 2 h |
| **前置** | `C05`, `C12`, `C16`, `C22`, `C24` |
| **阻擋** | 無 |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** Demo 演示者
**I want** 五個模式看起來像同一個產品
**so that** 切換模式時觀眾不會覺得是三個不同的網頁拼起來的

## 為什麼是這個順序

五個模式由五個 story 各自開發（這是平行化的代價），視覺很容易漂移。這個 story 是收尾的統一工作，**必須排在最後**。

## 範圍

**包含**
- 統一色彩：語意化 token（`--status-good` / `--status-warn` / `--status-bad`）
- 統一字級階層與間距尺度
- 統一按鈕、卡片、輸入框樣式
- 投影模式：一鍵放大所有字級 130%（Demo 用）
- 檢查所有文字對比度

**不包含**（避免範圍蔓延）
- 功能改動（純視覺）

## 實作

既有的 `:root` 已經有不錯的基礎（`--bg`、`--surface`、`--accent`、`--good`、`--warn`）。這個 story 把它擴充成完整的語意 token 集，並確保五個模式都只用 token、不寫死顏色。

**投影模式是實用需求**：Demo 時投影機解析度通常比你的螢幕低，而且觀眾坐得遠。一鍵放大 130% 比臨時用瀏覽器縮放好——瀏覽器縮放會讓 canvas 模糊，而 CSS 變數放大是銳利的。

對比度檢查：深色主題下最容易出問題的是 `--text-dim`（`#8b968e`）在 `--surface`（`#141915`）上——這對是 4.8:1，勉強過 WCAG AA。但投影機的對比度遠低於螢幕，建議把 dim 文字調亮一點。

## 驗收條件

- [ ] 五個模式視覺一致
- [ ] 所有顏色來自 token，無寫死值
- [ ] 投影模式一鍵切換
- [ ] 主要文字對比度 ≥ 4.5:1
