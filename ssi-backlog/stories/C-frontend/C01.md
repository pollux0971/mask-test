## Story

**As a** 使用者
**I want** 一個左側固定的模式列與右側可切換的主內容區
**so that** 監測、錄製、測驗、驗證、回放五種工作都在同一個介面裡，不用開不同網頁

## 為什麼是這個順序

**這是 C 軌的地基 story，25 個前端 story 有 20 個掛在它下面。** 現在的 `panel.html` 是單一畫面 663 行，硬塞五種模式會變成不可維護的一坨。先把外殼與模式概念立起來，其他 story 才能各自獨立開發。

## 範圍

**包含**
- `panel.html` 拆成 `monitor/panel/` 多檔（`index.html` + `js/` + `css/`）
- 版面：左側固定寬 200px 側邊欄，右側 flex 主內容區
- 五個模式的空殼容器（各一個 `<section>`，只有一個 `.active`）
- 既有的樣式變數（`--bg`、`--accent` 等）搬進 `css/tokens.css`
- 無建置工具，維持原生 ES module + `<script type="module">`

**不包含**（避免範圍蔓延）
- 任何模式的實際內容（C05 之後各自負責）
- 切換邏輯（C02）
- 狀態保存（C03）

## 實作

```
monitor/panel/
├── index.html          外殼 + 五個空 section
├── css/
│   ├── tokens.css      既有的 :root 變數搬過來
│   ├── shell.css       側邊欄 + 版面
│   └── modes/*.css     各模式樣式，一模式一檔
└── js/
    ├── main.js         啟動、SSE 連線
    ├── shell.js        側邊欄與模式路由（C02/C03）
    ├── bus.js          事件匯流排（C03）
    └── modes/*.js      一模式一檔
```

**維持零建置。** 你的 bridge 是 stdlib `http.server`，加 webpack/vite 會讓「跑起來」這件事多兩個步驟，而這個專案的使用者只有你自己。原生 ES module 在現代瀏覽器完全夠用。

`bridge_server.py:_serve_panel()` 目前只服務單一檔案，要改成服務整個 `panel/` 目錄（加一個簡單的靜態檔案 handler，注意路徑遍歷防護——既有的 `_serve_voice_file()` 已經示範了 `Path(...).name` 的做法）。

**一模式一個 JS 檔是刻意的**：這樣 C05–C24 這些 story 各自只改自己的檔案，平行開發不會衝突。
