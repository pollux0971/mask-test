# C22 — 驗證模式：實驗執行器

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E5 物理驗證 |
| **估時** | 3 h |
| **前置** | `C03`, `B18`, `D15` |
| **阻擋** | `C23` |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** 研究者
**I want** 從 UI 一鍵執行 C₀ / A / B / C / E 五個實驗
**so that** 實驗流程可重現，不用背指令與手動切換裝置狀態

## 為什麼是這個順序

實驗 C₀ 需要在三種感測器組態間精確切換並各錄 30 秒。手動操作容易出錯且不可重現；做成引導式流程，每次執行的條件都一致。

## 範圍

**包含**
- 五個實驗的卡片，各顯示：目的、通過標準、上次結果
- 引導式執行：每步顯示要做什麼（「請保持靜止 30 秒」），自動控制裝置狀態
- 執行中的即時進度
- 完成後顯示 PASS / FAIL 與關鍵數值

**不包含**（避免範圍蔓延）
- 分析演算法（D10–D14）
- 報告檢視（C23）

## 實作

以實驗 C₀ 為例的引導流程：

```
步驟 1/4  關閉感測器 B，請保持靜止        [自動: SENS:B=0]  30s ▓▓▓░
步驟 2/4  關閉感測器 A、開啟 B，保持靜止   [自動: SENS:A=0,B=1]
步驟 3/4  兩顆同時開啟，保持靜止          [自動: SENS:A=1,B=1]
步驟 4/4  分析中...
結果      Δ_dist = 1.3 mm  ✓ PASS (< 2 mm)
```

**裝置狀態的切換必須自動（透過 B18），不能靠人記得下指令。** 這是「可重現」的關鍵——三個月後重跑這個實驗，流程一模一樣。

「上次結果」讓你能快速比較：換了骨架之後 SNR 有沒有變好？

## 驗收條件

- [ ] 五個實驗都能從 UI 執行
- [ ] 裝置狀態切換自動且正確
- [ ] 執行中有明確進度
- [ ] 結果顯示 PASS/FAIL 與關鍵數值
- [ ] 上次結果可比較
