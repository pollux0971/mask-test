## Story

**As a** 開發者與 Demo 演示者
**I want** 載入並播放已存的 session
**so that** 我能離線調視覺化，也能在硬體出事時繼續 Demo

## 為什麼是這個順序

C 軌 25 個 story 有一半需要反覆調視覺化。每次都戴上裝置說話不現實。而且這是 E08 失敗備援的核心。

## 範圍

**包含**
- session 檔案選擇器（列出 `data/sessions/`）
- 播放控制：播放/暫停、速度（0.25× / 1× / 4×）、單步、trial 跳轉
- 時間軸與 trial 標記
- 回放中所有其他模式照常運作（用回放資料）
- **明顯的 REPLAY 標記**

**不包含**（避免範圍蔓延）
- 後端回放（B17）

## 實作

**回放模式的特殊之處：它不是一個「畫面」，而是一個「資料來源」。** 切到回放模式選好檔案按播放之後，你可以再切到監測模式看熱力圖、切到測驗模式跑辨識——資料都來自回放。

這個設計讓 B17 的價值最大化：一份錄好的 session 可以用來測試所有其他模式。

**REPLAY 標記要橫跨整個介面**（C04 的狀態列 + 主內容區的浮水印），不能只在回放模式裡標。因為使用者會切走，切走之後就看不到標記了——然後在監測模式盯著回放資料以為是即時的。

trial 跳轉讓你能直接跳到「第 34 筆，label=五」重複觀察。
