# C12 — 錄製模式：trial 提示卡與倒數

| 欄位 | 值 |
|---|---|
| **軌道** | C 前端 |
| **Epic** | E2 資料集 |
| **估時** | 2.5 h |
| **前置** | `C11`, `B11`, `B12` |
| **阻擋** | `C13` |
| **需要硬體** | 否 |
| **可平行於** | A/B/D 軌全部 |

## Story

**As a** 受試者
**I want** 大而清楚的提示：現在要念哪個詞、什麼時候開始
**so that** 我的時序一致，不用一邊看小字一邊記

## 為什麼是這個順序

受試者（通常就是你）如果要瞇著眼找提示，反應時間會不一致，錄下的樣本時序就不一致。提示要大到餘光可見。

## 範圍

**包含**
- 全螢幕大字提示（目標詞至少 120px）
- 倒數動畫 + 可選的嗶聲
- CAPTURE 期間明顯的視覺狀態（例如整個邊框變色）
- 空白鍵 Hold-to-Record 綁定
- ESC 放棄當前 trial

**不包含**（避免範圍蔓延）
- 進度清單（C13）
- 後端狀態機（B11）

## 實作

狀態的視覺對應：

| 狀態 | 視覺 |
|---|---|
| PROMPT | 詞顯示，邊框中性 |
| COUNTDOWN | 倒數數字 3-2-1，邊框漸變 |
| CAPTURE | **邊框變成明顯的紅色**，詞持續顯示 |
| SAVE | 短暫的確認勾號 |
| REST | 淡出，顯示下一個詞的預告 |

**CAPTURE 狀態的視覺必須強烈**，因為受試者的注意力在念詞上，需要用餘光就能知道「現在在錄」。整個邊框變色比一個小紅點有效得多。

嗶聲用 Web Audio API 的 `OscillatorNode`，不要載入音檔（維持零建置）。要可關閉——連續錄 72 筆的嗶聲會讓人抓狂。

空白鍵綁定要 `preventDefault()`，否則會捲動頁面。
