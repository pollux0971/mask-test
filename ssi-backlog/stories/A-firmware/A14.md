# A14 — 音框 hop 改為 256（50% 重疊）

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E3 音訊特徵 |
| **估時** | 2 h |
| **前置** | `A12` |
| **阻擋** | `D02` |
| **需要硬體** | 是 |
| **可平行於** | B/C/D 軌全部 |

## Story

**As a** DTW 對齊
**I want** 更密的時間解析度
**so that** 一個短詞能有足夠多的音框供比對

## 為什麼是這個順序

512 無重疊 = 32 ms/幀，一個 400 ms 的詞只有 12 幀。DTW 在 12 幀上對齊很不穩定。改成 256 hop（16 ms）給你 25 幀。

## 範圍

**包含**
- 環形緩衝，每 256 個新 sample 觸發一次 512 窗的 FFT
- `$F` 輸出頻率變成 62.5 Hz
- 重新量測頻寬與 CPU

**不包含**（避免範圍蔓延）
- `$M` 的 RMS 頻率（維持 31 Hz 即可，不需要那麼密）

## 實作

需要一個 512 samples 的環形緩衝：讀進 256 個新 sample，與前 256 個組成 512 的窗。

```c
static int16_t s_ring[512];
/* 每次讀 256 → memmove 前半，新資料放後半 → FFT 整個 512 */
```

**這是 A 軌唯一一個「純調優」的 story，可以最後做。** 若時程緊，維持 512 hop 也能運作，只是 DTW 品質稍差。D05 的驗收會告訴你 12 幀夠不夠——若 DTW 準確率已達標，這個 story 可以直接砍掉。

頻寬要重驗：`$F` 從 7.8 → 15.6 KB/s，總計約 25 KB/s（54%）。

## 驗收條件

- [ ] `$F` 穩定 62.5 Hz
- [ ] 總頻寬使用率 < 70%（由 A13 加的計數器讀取）
- [ ] ToF 掉幀率仍 < 1%
- [ ] 與 librosa 相同參數（hop=256）的結果相關係數 > 0.95
