# A03 — $M 行：新標籤 + 序號 + 時間戳

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E1 訊號地基 |
| **估時** | 1 h |
| **前置** | `T01` |
| **阻擋** | `B01`, `B04` |
| **需要硬體** | 是 |
| **可平行於** | A01/A02 之外的全部 |

## Story

**As a** 時鐘對齊模型
**I want** 麥克風的每一幀也帶 `seq` 與 `t_us`
**so that** 音訊與 ToF 能放到同一條時間軸上

## 為什麼是這個順序

ToF 有時間戳但音訊沒有，等於只完成一半——跨模態對齊需要兩邊都有。

## 範圍

**包含**
- `mic_task()` 的 printf 改成 `$M,<seq>,<t_us>,<rms>,<peak>`
- 時間戳在 `i2s_channel_read()` 回傳後立刻取

**不包含**（避免範圍蔓延）
- Mel（A12）
- 錄音 dump 的時間戳（A07 處理）

## 實作

檔案：`main/bone_mic.c:mic_task()`

音訊有個 ToF 沒有的細節：`i2s_channel_read()` 回傳的是**這一批 512 個 sample 的結尾**，不是開頭。DMA 已經填好 buffer 才回來。所以：

```c
int64_t t_end = esp_timer_get_time();
int64_t t_start = t_end - (int64_t)n * 1000000 / MIC_SAMPLE_RATE_HZ;
```

**送 `t_start`（音框第一個 sample 的時間），不是 `t_end`。** 512 samples @16 kHz = 32 ms，這個差距比你要量的唇動與發聲時間差（50–150 ms）小不了多少，搞錯方向就會系統性偏移一整個音框。把這個決定寫進 `CONTRACTS.md`。

## 驗收條件

- [ ] `$M` 行以 ~31 Hz 穩定輸出（512 hop）
- [ ] `t_us` 差值穩定在 32000 ± 2000 µs
- [ ] `CONTRACTS.md` 註明 `t_us` 是音框起點
