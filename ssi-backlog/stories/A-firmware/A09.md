# A09 — PING 指令：主動校時取樣

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E1 訊號地基 |
| **估時** | 0.5 h |
| **前置** | `A07` |
| **阻擋** | `B05` |
| **需要硬體** | 是 |
| **可平行於** | 全部 |

## Story

**As a** 時鐘對齊模型
**I want** 主動要求裝置立刻回報時間
**so that** 我能在 session 開始與結束時各取一次乾淨的校時樣本

## 為什麼是這個順序

被動等 `$H` 心跳來校時，取樣點受排隊延遲影響。主動 PING 可以在 UART 空閒時發出，往返延遲最短、最接近真實時鐘差。

## 範圍

**包含**
- 解析 `PING`，立刻輸出一行 `$H`
- 優先權高於一般輸出（取得 `uart_out_lock` 後立即印）

**不包含**（避免範圍蔓延）
- 主機端的往返時間計算（B05）

## 實作

實作很簡單，但有個細節：`PING` 的回應要盡量減少排隊。目前 `uart_out_lock()` 是 FIFO 互斥鎖，如果剛好有 `$T` 在排隊，PING 回應會晚 1–2 ms。

對 5 ms 的對齊目標來說這是可接受的（B04 的驗收是殘差 p95 < 5 ms），所以**不要為此做優先權佇列**——複雜度不划算。但要在 `CONTRACTS.md` 註明「PING 回應含最多 2 ms 的排隊延遲」，讓 B05 知道要用最小值統計而不是平均值。

## 驗收條件

- [ ] 送出 `PING` 後 5 ms 內收到 `$H`
- [ ] 連續 100 次 PING 的往返時間，p95 < 10 ms
- [ ] PING 不影響 `$T` / `$M` 的連續性
