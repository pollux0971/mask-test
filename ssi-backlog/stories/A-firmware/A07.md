# A07 — $STATUS 加入協定版本與韌體識別

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E1 訊號地基 |
| **估時** | 1 h |
| **前置** | `T01` |
| **阻擋** | `B02` |
| **需要硬體** | 是 |
| **可平行於** | 全部 |

## Story

**As a** bridge
**I want** 開機時知道對方是哪個協定版本、哪個 commit 的韌體
**so that** 我能自動選擇解析器，且資料集能記錄產生它的韌體版本

## 為什麼是這個順序

平行開發期間你會頻繁在新舊韌體之間切換。沒有版本協商，bridge 會靜默地解析錯誤而不是報錯。

## 範圍

**包含**
- `$STATUS,res=<dim>,proto=2,fw=<sha>`
- 開機時印一次，收到 `PING` 時再印一次
- git sha 由 CMake 在編譯時注入

**不包含**（避免範圍蔓延）
- bridge 端的相容邏輯（B02）

## 實作

CMake 注入 git sha：

```cmake
execute_process(COMMAND git rev-parse --short HEAD
                OUTPUT_VARIABLE GIT_SHA OUTPUT_STRIP_TRAILING_WHITESPACE)
add_compile_definitions(FW_GIT_SHA="${GIT_SHA}")
```

`fw` 欄位會被寫進每個 HDF5 session 的 metadata（T02 已預留）。三個月後回頭看某批資料很奇怪時，這個欄位讓你能 `git checkout` 回去看當時的韌體到底在做什麼。
