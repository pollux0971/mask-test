# A15 — 韌體效能回歸測試

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E1 訊號地基 |
| **估時** | 2 h |
| **前置** | `A06`, `A12` |
| **阻擋** | `E01` |
| **需要硬體** | 是 |
| **可平行於** | B/C/D 軌全部 |

## Story

**As a** A 軌開發者
**I want** 一套可重複執行的效能檢查
**so that** 每次改韌體後能立刻知道有沒有把時序弄壞

## 為什麼是這個順序

A 軌改了 14 個 story，每個都可能影響時序。手動確認 14 次不現實，需要一個能一次跑完的檢查清單。

## 範圍

**包含**
- 固定情境跑 5 分鐘，收集：幀率、幀間隔標準差、掉幀率、heap 趨勢、stack 餘裕、頻寬使用率
- 四種組態各跑一次：4×4+Mel、4×4−Mel、8×8+Mel、8×8−Mel
- 產出對照表

**不包含**（避免範圍蔓延）
- 自動化 CI（手動跑腳本即可）

## 實作

主機端腳本，讀 5 分鐘的 `$H` 與 `$T` / `$F` 並產表：

```bash
python3 tools/fw_regression.py --port /dev/ttyUSB0 --duration 300 --out reports/A15/
```

## 驗收條件

- [ ] 四種組態全部量測完成並產表

- [ ] 結果存進 `reports/A15/`，含 git sha
