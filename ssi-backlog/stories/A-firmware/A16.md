# A16 — `$A` ambient 幀與 AMB 指令

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E1 訊號地基 |
| **估時** | 1.5 h |
| **前置** | `A01`（`$T` 的 seq/t_us 模式）、`A08`（uart_cmd 指令解析骨架） |
| **阻擋** | `D10`, `E02` |
| **需要硬體** | 是（驗證需要，實作不需要） |
| **可平行於** | 全部 |

## Story

**As a** crosstalk 分析（`D10`）
**I want** 讀得到每個 zone 的 `ambient_per_spad`
**so that** 我能在距離偏移顯現**之前**就偵測到兩顆感測器互相干擾

## 為什麼會有這個 story

`D10.md` 明訂 `ambient_per_spad` 是 crosstalk **最靈敏**的指標，
但 `D10` 開工時才發現：**這個欄位從韌體、序列埠協定到 HDF5 schema，
整條管線都不存在**。感測器讀得到（ULD 的 `VL53L7CX_ResultsData` 有這個陣列），
只是從來沒有人把它送出來。

`T01`／`T02` 凍結時沒有涵蓋它，因為當時沒有人在做 `D10`。

## 範圍

**包含**
- `$A,<A|B>,<seq:u32>,<t_us:i64>,<dim>,<a0>..<aN>` 輸出（見 `CONTRACTS.md` §1.1.3）
- `AMB:<0|1>` 指令解析（`uart_cmd.c`），**預設關閉**
- 開啟時以 **1 Hz** 輸出（不要跟著 ToF 的 30 Hz 走）
- `AMB` 改變組態後重發 `$STATUS`（§1.1）
- `$A` 有**自己獨立的 `seq`**（§1.1.1，第五條串流）

**不包含**（避免範圍蔓延）
- 主機端解析（`B01` 的範圍）
- HDF5 寫入（`B07` 的範圍）
- 分析（`D10` 的範圍）
- 把 ambient 塞進 `$T`（**明確排除**，見下）

## 為什麼是獨立一行而不是加進 `$T`

`ambient_per_spad` 變化很慢，不需要 30 Hz。
若塞進 `$T` 每一幀，8×8 會多約 **190 bytes/行**——
而 `CONTRACTS.md` §1.4 顯示 8×8 開 Mel 已經到 **70%** 頻寬，再加就爆。

而 `D10`／`E02` 是**專門的短時實驗**，不是持續監測，開一個旗標跑一段就好。

## 實作提示

- 值的縮放 `ambient_per_spad / 100`，四捨五入（與 `$T` 的 signal 同慣例）
- 無效 zone（`target_status ∉ {5,9}`）回 `-1`
- 1 Hz 的節流用 `esp_timer_get_time()` 比對，不要用計數器除法
  （ToF 幀率會變，除法會漂）
- `uart_cmd.c` 的 `AMB:` 解析比照 `MEL:` 的嚴格寫法：
  只接受 `AMB:0` / `AMB:1`，其餘拒絕且**不重發** `$STATUS`
- 送出的 bytes 記得接 `uart_out_add_bytes()`（`A15` 的頻寬計數）

## 驗收條件

- [ ] `AMB:1` 後 `$A` 以 ~1 Hz 輸出，兩顆各一行
- [ ] `AMB:0` 後 `$A` 停止，`$T`/`$M`/`$F` 不受影響
- [ ] `$A` 的 `seq` 獨立遞增、無跳號
- [ ] 行格式與 `CONTRACTS.md` §1.1.3 完全一致
- [ ] 遮住一顆感測器時，另一顆的 ambient 讀值有可觀察的變化（🔧 需上機）
- [ ] `AMB:1` 開啟後總頻寬增加 < 2%（用 `A15` 的 `bw_bytes_since_last` 量）
