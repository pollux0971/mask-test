# A06 — $H 心跳行

| 欄位 | 值 |
|---|---|
| **軌道** | A 韌體 |
| **Epic** | E1 訊號地基 |
| **估時** | 1.5 h |
| **前置** | `A05` |
| **阻擋** | `B01`, `C04` |
| **需要硬體** | 是 |
| **可平行於** | B/C/D 軌全部 |

## Story

**As a** 主機端
**I want** 每秒一行的系統健康摘要
**so that** 我能在 panel 上顯示裝置狀態，並在連線正常但資料異常時分辨出來

## 為什麼是這個順序

目前 panel 的連線指示燈只知道「有沒有收到東西」。心跳行讓它能顯示「收到東西，但裝置說它掉了 12% 的幀」——這是完全不同的資訊。

## 範圍

**包含**
- `$H,<t_us>,<drop_A>,<drop_B>,<drop_M>,<heap>,<temp_c>`
- 獨立的 1 Hz task，或掛在 ToF 迴圈上計時
- `heap` 用 `esp_get_free_heap_size()`
- `temp_c` 用 `s_results[0].silicon_temp_degc`

**不包含**（避免範圍蔓延）
- ambient_per_spad（留給後續，欄位先預留）

## 實作

溫度值得特別注意：VL53L7CX 的 `silicon_temp_degc` 在長 session 中會漂移，而 ToF 距離讀值有溫度相依性。錄一小時的資料，前後基線可能差好幾 mm——如果沒記錄溫度，這個漂移會被誤判成「戴法跑掉了」。

`heap` 監控是為了 A12：Mel 計算會配置 FFT buffer，若有洩漏，heap 會緩慢下降，跑幾小時才會崩。心跳行讓你在 panel 上直接看到趨勢。

## 驗收條件

- [ ] `$H` 穩定 1 Hz 輸出
- [ ] `heap` 在連續運作 30 分鐘後不下降超過 2 KB
- [ ] 溫度值合理（室溫下 25–45 °C）
- [ ] 心跳行不干擾 `$T` / `$M` 的時序（幀間隔標準差不變）
