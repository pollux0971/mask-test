# B06 — 多模態時間對齊器

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E1 訊號地基 |
| **估時** | 3 h |
| **前置** | `B01`, `B04` |
| **阻擋** | `B07`, `B11`, `D09` |
| **需要硬體** | 否 |
| **可平行於** | A/C/D 軌全部 |

## Story

**As a** 特徵抽取與辨識引擎
**I want** 一個把 `$T`(A) / `$T`(B) / `$M` / `$F` 併成同步幀的元件
**so that** 下游拿到的是對齊好的多模態序列，不是四條各自為政的串流

## 為什麼是這個順序

四條串流的頻率都不同（ToF 30 Hz、Mic 31 Hz、Mel 62.5 Hz），而且不同步。每個下游元件都自己對齊會重複實作且容易出錯。

## 範圍

**包含**
- 各模態的環形緩衝（保留最近 10 秒）
- 以指定的目標頻率（預設 ToF 的 30 Hz）產生對齊幀
- 最近鄰或線性內插，可設定
- 缺資料時標記而非填 0

**不包含**（避免範圍蔓延）
- 特徵正規化（D01/D02）
- trial 切分（B11）

## 實作

```python
class Aligner:
    def frames(self, t_start_us, t_end_us, rate_hz=30):
        """yield AlignedFrame(t_us, tof_A, tof_B, mic_rms, mel, valid_mask)"""
```

**設計決定：以 ToF 為時基。** ToF 是最慢也最不可內插的（距離跳變是真實的物理事件，內插會製造不存在的中間值）。Mel 比較密，可以往 ToF 的時間點取最近鄰。

**缺資料一定要用 mask 標記，不要填 0。** 填 0 在 z-score 之後會變成一個「距離特別近」的假訊號，而且分析時完全看不出來。這與 T02 用 `tof_valid_*` 布林陣列是同一個原則。

這個元件是純函式（輸入緩衝 → 輸出幀序列），**應該有完整單元測試**：餵已知時間戳的假資料，檢查對齊結果。

## 驗收條件

- [ ] 輸出幀的 `t_us` 間隔穩定在 1/rate ± 1 ms
- [ ] 任一模態缺資料時，該欄位的 mask 為 False 而非填值
- [ ] 單元測試涵蓋：正常、單模態缺失、時間戳亂序、大 gap
- [ ] 處理 10 秒資料耗時 < 50 ms
