## Story

**As a** bridge
**I want** 解析 `$T` / `$M` / `$F` / `$H` 四種新行
**so that** 前端能收到帶時間戳的結構化事件

## 為什麼是這個順序

T04 的 mock device 一跑起來就能開發這個，完全不需要等 A 軌燒錄成功。這是 B 軌的第一個 story。

## 範圍

**包含**
- `parse_line()` 擴充四種新行型別
- 整數解析失敗時回 `None` 而非拋例外
- `-1` 轉成 `None` 或配合 valid mask
- 單元測試涵蓋每種行的正常與畸形輸入

**不包含**（避免範圍蔓延）
- v1 相容（B02）
- 掉幀偵測（B03）
- 時間對齊（B06）

## 實作

檔案：`monitor/bridge_server.py:parse_line()`

現有實作用 `line.split(",")` 加 try/except，可以沿用，但要處理一個新問題：**`$T` 行現在有 `2 × dim` 個值，長度會變**。不要寫死長度，用行內自帶的 `dim` 推：

> ⚠️ **`dim` 是 zone 數本身，不是邊長**（`CONTRACTS.md` §1.1：4×4 → `dim=16`、8×8 → `dim=64`）。
> 所以是 `2 × dim`，**不是 `2 × dim²`**。這份文件原本寫成 `dim * dim`，是錯的。

```python
if len(values) < 2 * dim:      # §1.1 前向相容：檢查「至少」，不是 `!=`
    return None                # 畸形，計數後丟棄
dist, sig = values[:dim], values[dim:2 * dim]
```

⚠️ **不要用 `assert`**——本 story 自己的驗收條件就寫著「畸形行**不拋例外**」。
回傳 `None` 並計數，讓呼叫端決定怎麼處理。

畸形行不要靜默丟棄——計數並在 `$H` 事件裡帶出去。UART 偶發位元錯誤在 460800 baud 下是會發生的，你要知道發生率。

> **實際發生率的來源不只 UART 位元錯誤**：`reports/BOOT_OUTPUT.md` 證明
> 韌體的 `ESP_LOG*` 不走 `uart_out_lock()`，會把一行 `$T` 從中間切開。
> 那種殘缺行也會被這個檢查擋下，並計入 `malformed`。

**這個 story 應該有真正的單元測試**（`tests/test_parse.py`），因為它是純函式、輸入輸出明確，測試成本極低而回報很高。
