# B01 — 解析協定 v2 行格式

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E1 訊號地基 |
| **估時** | 2 h |
| **前置** | `T01`, `T04` |
| **阻擋** | `B03`, `B06`, `C04` |
| **需要硬體** | 否（用 mock device） |
| **可平行於** | A/C/D 軌全部 |

## Story

**As a** bridge
**I want** 解析 `$T` / `$M` / `$F` / `$H` 四種新行
**so that** 前端能收到帶時間戳的結構化事件

## 為什麼是這個順序

T04 的 mock device 一跑起來就能開發這個，完全不需要等 A 軌燒錄成功。這是 B 軌的第一個 story。

## 範圍

**包含**
- `parse_line()` 擴充四種新行型別
- 整數解析失敗時回 `None` 而非拋例外
- `-1` 轉成 `None` 或配合 valid mask
- 單元測試涵蓋每種行的正常與畸形輸入

**不包含**（避免範圍蔓延）
- v1 相容（B02）
- 掉幀偵測（B03）
- 時間對齊（B06）

## 實作

檔案：`monitor/bridge_server.py:parse_line()`

現有實作用 `line.split(",")` 加 try/except，可以沿用，但要處理一個新問題：**`$T` 行現在有 `2 × dim²` 個值，長度會變**。不要寫死長度，用 `dim` 推：

```python
n = dim * dim
dist, sig = vals[:n], vals[n:2*n]
assert len(sig) == n, f"malformed $T: expected {2*n} values, got {len(vals)}"
```

畸形行不要靜默丟棄——計數並在 `$H` 事件裡帶出去。UART 偶發位元錯誤在 460800 baud 下是會發生的，你要知道發生率。

**這個 story 應該有真正的單元測試**（`tests/test_parse.py`），因為它是純函式、輸入輸出明確，測試成本極低而回報很高。
