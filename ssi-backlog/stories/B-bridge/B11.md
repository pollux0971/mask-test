## Story

**As a** 錄製流程
**I want** 一個 PROMPT → COUNTDOWN → CAPTURE → SAVE → REST 的狀態機
**so that** 每筆樣本的時序結構一致

## 為什麼是這個順序

手動抓時間錄製會產生長度不一、前後留白不一的樣本，這種變異會直接污染 CV（實驗 B）與 Silhouette（實驗 C）。

## 範圍

**包含**
- 狀態機核心，狀態變更透過 SSE 廣播
- 詞序隨機打散（可設 seed 重現）
- 中途放棄不留半筆資料
- `POST /trial/abort`、`/trial/redo`

**不包含**（避免範圍蔓延）
- 觸發方式（B12/B13）
- 前端 UI（C12）

## 實作

```
IDLE ──► PROMPT(1.5s) ──► COUNTDOWN(0.5s) ──► CAPTURE(2.0s)
      ──► SAVE ──► REST(1.5s) ──► 下一個 / IDLE
```

**詞序打散要記錄 seed。** 如果 Silhouette 結果異常，你會想知道是不是某個特定順序造成的（例如連續三次同一個詞導致疲勞）。有 seed 就能重現。

放棄的 trial 要**完全不寫入**，不要寫了再刪——HDF5 刪除 group 不會回收空間，而且 manifest 會不一致。狀態機在 SAVE 之前保持在記憶體，確認後才落盤。

狀態機是純邏輯，**應該可以不接硬體就用假時鐘測試**：注入一個 `clock` 依賴，測試時用假時鐘快轉。

## 驗收條件

- [ ] 每個 trial 的 ToF 幀數 = 期望值 ± 2（2 s × 30 Hz = 60）
- [ ] abort 後 HDF5 與 manifest 都沒有該筆
- [ ] 相同 seed 產生相同詞序
- [ ] 單元測試用假時鐘跑完整流程，不需硬體
