# B09 — Session metadata API

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E2 資料集 |
| **估時** | 1.5 h |
| **前置** | `B07` |
| **阻擋** | `C11` |
| **需要硬體** | 否 |
| **可平行於** | A/C/D 軌全部 |

## Story

**As a** 前端錄製模式
**I want** 一組建立與查詢 session 的 HTTP 端點
**so that** 我能在 UI 上填表單開始一個 session

## 為什麼是這個順序

C 軌需要一個明確的 API 契約才能開發錄製模式的表單，而不用知道 HDF5 怎麼寫。

## 範圍

**包含**
- `POST /session/start`（body: metadata）→ session_id
- `POST /session/end`
- `GET /session/current`
- 必填欄位驗證，缺欄位回 400 並指名缺哪個
- 上一次的設定持久化到 `config/last_session.json` 供預填

**不包含**（避免範圍蔓延）
- 前端表單（C11）
- baseline 錄製（B10）

## 實作

必填欄位（依 T02 schema）：`subject`、`wear_id`、`mode`、`distance_mm`、`angle_deg`、`ambient`。

**`wear_id` 要做成「自動遞增但可覆寫」**：預設是上次 +1，因為使用者通常是重新戴上；但有時是同一次戴上繼續錄，這時要能改回相同值。實驗 B（S5.3 / D12）完全依賴這個欄位的正確性——它區分「同次戴」與「跨次戴」。

回應要帶 `warnings`：例如「距離 25 mm 偏離目標 17 mm」，不阻擋但提醒。

## 驗收條件

- [ ] 缺必填欄位回 400 且訊息指名欄位
- [ ] `GET /session/current` 在未開始時回 204
- [ ] 上次設定正確預填
- [ ] 重複 start 回 409
