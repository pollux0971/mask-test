# B02 — v1 / v2 雙協定相容

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E1 訊號地基 |
| **估時** | 1 h |
| **前置** | `B01`, `A07` |
| **阻擋** | 無 |
| **需要硬體** | 否 |
| **可平行於** | A/C/D 軌全部 |

## Story

**As a** 開發者
**I want** bridge 能同時支援新舊韌體
**so that** 我在燒錄新舊版本之間切換時不需要改主機端程式

## 為什麼是這個順序

平行開發期間你會頻繁切換韌體版本（例如回去驗證某個 bug 是不是新引入的）。沒有相容層，每次切換都要改兩邊。

## 範圍

**包含**
- 由 `$STATUS` 的 `proto=` 決定解析器
- 無 `proto=` 時預設 v1
- panel 顯示當前協定版本

**不包含**（避免範圍蔓延）
- v1 韌體的新功能模擬（不做，v1 就是沒有）

## 實作

```python
PARSERS = {1: parse_line_v1, 2: parse_line_v2}
proto = {"version": 1}   # 由 $STATUS 更新
```

`$STATUS` 是唯一在兩個版本中格式相同的行，所以它必須用一個 version-agnostic 的解析器（目前的 regex `res=(\d+)` 剛好就是）。

**v1 模式下要在 panel 顯示明顯的警告**：「協定 v1 — 無時間戳，資料不可用於驗證分析」。否則你會不小心用 v1 韌體錄了一整個 session 的資料才發現沒有時間戳。
