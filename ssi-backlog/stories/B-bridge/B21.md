# B21 — VAD 完整接線與 speaking_mode 值域分離

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E2 錄製流程 |
| **估時** | 2.0 h |
| **前置** | `B11`, `B15`, `B16`, **`/trial/*` 的 wiring 完成** |
| **阻擋** | `D14` 的真實結論、`E05` 的資料品質 |
| **需要硬體** | 否 |
| **可平行於** | C 軌全部 |

## Story

**As a** `E05` 錄下來的每一筆 trial
**I want** `vad_*` / `lip_onset_us` / `voice_onset_us` 是真的偵測結果，
且 `speaking_mode` 不會讓整個 session 炸掉
**so that** `D14` 的 viseme 分析與「唇動先行量」有真實數字可用

## 為什麼會有這個 story

`C13` 完成時回報了兩個問題，**都不是它能自己拍板的**：

### 1. VAD 完整接線需要改建構子簽章

`B11` 目前把四個 VAD 欄位填 `None`（已符合 §2，不再填視窗邊界），
但**沒有真的呼叫 `B15`/`B16`**。原因：

- `detect_from_events()` 要吃 **`ProtocolParser` 的原始事件**
  （含 `type`/`sensor`/`distance`/`t_us`），不是 `Aligner.frames()`
  產生的 `AlignedFrame`——`_do_save()` **完全沒有保留原始事件串**
- 需要 `baseline_mu`/`baseline_sigma` **在建構時就餵進來**，
  而 `TrialStateMachine.__init__` 現在沒有這個參數
- **那個建構子正是 `/trial/*` wiring 的呼叫點**，
  貿然改簽章會跟 wiring 的工作打架

### 2. 🔴 `speaking_mode` 值域衝突會讓 session 當場炸掉

| 來源 | 值 |
|---|---|
| 錄製表單的 `mode` 欄位（`C11`） | **自由文字**，datalist 建議裡還有 `quiz` |
| `session_writer.VALID_SPEAKING_MODES` | **`{normal, whisper, silent}`** |

若把 `self._mode` 直接當 `speaking_mode` 傳下去，
**使用者只要填了那三種以外的值，就會在 `SAVE` 當下拋 `ValueError`**——
而那是錄到一半的時候，整個 session 掛掉。

**根因**：契約 §2 已經明訂 `mode`（session／面板模式）與
`speaking_mode`（說話模式）**是兩條不同的軸**，
但 `C11` 的表單只有一個 `mode` 欄位。

## 範圍

**包含**
- `C11` 的錄製表單新增**獨立的 `speaking_mode` 三選一**
  （`normal` / `whisper` / `silent`），與既有的 `mode` 欄位分開
  （`C15` 的測驗模式已經是分開的兩組按鈕，**照它的做法**）
- `TrialStateMachine` 接收 `speaking_mode`（**不是重用 `self._mode`**）
- `TrialStateMachine.__init__` 新增 `baseline_mu`/`baseline_sigma` 參數
- `_do_save()` 保留該 trial 期間的**原始事件串**（不只 `AlignedFrame`）
- 真的呼叫 `measure_lip_lead()`，四個 VAD 欄位填真值
- ⚠️ **`silent` 模式下 `voice_onset_us` 必然是 `None`、`lip_onset_us` 仍有值**
  （§2）——不可假設四個欄位同時存在或同時缺席

**不包含**（避免範圍蔓延）
- 放寬 `VALID_SPEAKING_MODES`（**明確排除**：那個值域是 `D13`/`D17`
  的「三種 mode 各跑一組」分析依賴的，放寬等於讓分析無法分群）
- 改 `mode` 欄位的自由文字性質（它是 session 類型，本來就該自由）
- `B15`/`B16` 的偵測邏輯本身

## ⚠️ 時機：必須等 `/trial/*` 的 wiring 完成

`TrialStateMachine.__init__` 的簽章是 `bridge_server.py` 的呼叫點。
**wiring 進行中改簽章會直接打架。**

→ 由調度員在 wiring 完成後派工，並確認**由同一個人或協調過的兩個人**做。

## 實作提示

- 原始事件串要**複製不是存參考**——`Aligner` 的緩衝會過期修剪
  （`C13` 在前端存 trial 預覽時踩過同一個坑）
- `baseline_mu`/`baseline_sigma` 來自 `B10` 的 `capture_baseline_trial()`，
  已經寫進 `/meta`；建構 `TrialStateMachine` 時 session 一定已經有 baseline
  （`baseline_done` 旗標擋著）
- `B16` 的介面：
  ```python
  from host.vad.tof_vad import detect_from_events as detect_lips, excluded_from_quality
  from host.vad.audio_vad import detect_from_events as detect_voice
  from host.vad.onset import measure_lip_lead
  lead = measure_lip_lead(lips, voice)
  attrs = lead.to_trial_attrs()   # 四個欄位，偵測不到是 None
  ```
- ⚠️ `detect_lips()` 的 `energy_mu`/`energy_sigma` **強烈建議從 baseline
  期間算好傳進去**——`B16` 實測自估會偏嚴約 23%
