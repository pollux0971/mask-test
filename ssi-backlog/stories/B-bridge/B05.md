# B05 — PING 主動校時

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E1 訊號地基 |
| **估時** | 1 h |
| **前置** | `B04`, `A09` |
| **阻擋** | 無 |
| **需要硬體** | 是（需 A09 已燒錄） |
| **可平行於** | A/C/D 軌全部 |

## Story

**As a** 時鐘對齊模型
**I want** 在 UART 空閒時主動取校時樣本
**so that** 我能拿到延遲最小、最乾淨的配對點

## 為什麼是這個順序

被動等 `$H` 心跳來校時，取樣點受排隊影響。主動 PING 可挑在流量低谷發出。

## 範圍

**包含**
- session 開始與結束時各連發 20 次 PING
- 記錄往返時間，取最小值的那次作為校時點
- 把這些點加權後餵給 B04

**不包含**（避免範圍蔓延）
- 韌體端實作（A09）

## 實作

```python
samples = []
for _ in range(20):
    t0 = time.perf_counter()
    ser.write(b"PING\n")
    h = wait_for_h(timeout=0.1)
    rtt = time.perf_counter() - t0
    samples.append((h.t_us, t0 + rtt/2, rtt))
best = min(samples, key=lambda s: s[2])    # RTT 最小 = 最乾淨
```

`t0 + rtt/2` 假設去程與回程延遲對稱。這對 UART 不完全成立（送出 4 bytes vs 收回 60 bytes），但誤差在 1 ms 量級，遠小於 5 ms 目標。

**session 結束也要做一次**：兩端點的校時讓你能算出這個 session 期間的實際時鐘漂移量，寫進 metadata 供事後檢查。

## 驗收條件

- [ ] 20 次 PING 中至少 15 次在 10 ms 內回應
- [ ] session 首尾各存一組校時點
- [ ] 漂移量寫進 metadata
