# B18 — SENS / MEL / 解析度控制端點

| 欄位 | 值 |
|---|---|
| **軌道** | B 主機橋接 |
| **Epic** | E1 訊號地基 |
| **估時** | 1 h |
| **前置** | `A08`, `A13` |
| **阻擋** | `C22` |
| **需要硬體** | 是 |
| **可平行於** | A/C/D 軌全部 |

## Story

**As a** 前端驗證模式
**I want** 透過 HTTP 控制感測器開關與 Mel 串流
**so that** Crosstalk 實驗能從 UI 一鍵執行

## 為什麼是這個順序

實驗 C₀ 需要精確地在三種組態間切換並各錄 30 秒。從 UI 按鈕觸發比手動打指令可靠得多，也可重現。

## 範圍

**包含**
- `POST /sensor?id=A&on=0`
- `POST /mel?on=0`
- 沿用既有的 `POST /switch?res=4|8`
- 狀態查詢 `GET /device/state`

**不包含**（避免範圍蔓延）
- 實驗流程編排（C22）

## 實作

既有的 `_handle_record()` 已經示範了寫入序列埠的模式（`serial_write_lock` + `ser.write()`），照抄即可。

**要處理 flashing 中的情況**：既有程式碼在 `flashing.is_set()` 時回 409，新端點也要一致。

`GET /device/state` 回傳目前的解析度、感測器開關、Mel 狀態、協定版本、韌體 sha——前端啟動時拉一次，之後靠 SSE 更新。

- [ ] flashing 中回 409
