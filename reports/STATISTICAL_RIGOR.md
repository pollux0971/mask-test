## 1. 🔴 多重比較：一輪報告做了 11 個檢定，零校正

### 現況

`grep -rn "bonferroni\|fdr\|multiple.compar" analysis/` → **完全沒有**。

一次 `python -m analysis.run_all` 產生的**顯著性檢定**（不含純門檻比較）：

| 來源 | 檢定 | 數量 |
|---|---|---|
| `D19` `run_ablation_suite()` | `_run()` 對 `all` / `mel` / `tof_combined` / `tof_l` / `tof_r` 各一次 permutation test | **5** |
| `D19` `random_channel` | 加噪版再一次 | **1** |
| `D19` `time_reversal` | 自己的 CV（不產 p 值，但產一個 pass/fail 判定） | 1（無 p） |
| **小計（有 p 值）** | | **6** |

若再加上獨立跑的 `D18`（`all` + `tof_only`）與 `D21`（三個）——
**完整的驗證流程會產生 11 個 p 值**。

### 委員會怎麼問

> 「你做了幾個檢定？有沒有校正？」

**11 個檢定、α = 0.01**，在虛無假設全為真的情況下，
至少出現一個「顯著」的機率是 `1 − 0.99¹¹ ≈ 10.5%`。

✅ **三個模組的 α 是一致的**：`D18` / `D19` / `D21` 的 `P_VALUE_THRESHOLD`
都是 `0.01`。（寫這份稽核時我一度以為 `D21` 用的是 `0.05`，去查證後發現
不是——**沒有查證就寫下來的話，這份文件自己就會變成一個查不到出處的
數字**。）

所以問題純粹是**檢定數量**，不是門檻不一致。

### 但先講清楚：**這不是「隨便亂槍打鳥」**

11 個檢定**不是**在同一個假設上反覆試。它們是**刻意設計的對照矩陣**：
`tof_l` / `tof_r` / `tof_combined` / `mel` / `all` 各自回答不同的問題，
而且**互相之間有預期關係**（`D15` 的跨實驗一致性檢查就是在驗那些關係）。

**這個區別本身就是給委員的答案**，但**必須主動講**，不能等被問。

### 最小修法提案（不動手）

**方案 A（建議）**：把「主要假設」與「次要／探索性」分開宣告。

* **主要假設只有一個**：**ToF-only 的分離度顯著**（`tof_combined`）。
  那是整個專案的核心主張，**用 α = 0.01 不校正，因為它是預先指定的單一假設**。
* **其餘全部標為 exploratory**，報告裡不宣稱「顯著」，只給效果量與 p 值供參考。

這是臨床試驗的標準做法（pre-registered primary endpoint），
**改動成本近乎零**——只要在 `format_report()` 加一段文字宣告，不用改任何計算。

**方案 B**：對六個 `D19` 的檢定做 Bonferroni（α = 0.01/6 ≈ 0.0017）。
⚠️ **但那跟第 2 項衝突**：置換 200 次的 p 值下限是 0.005，**永遠達不到 0.0017**。
所以方案 B **必須**配合把置換次數提到至少 1000。

## 2. ✅ 置換次數：預設 200，p 值下限是 0.005 — **已修**

> **2026-08-26 修正**：`d18_permutation_test.py` 新增 `p_value_floor(n)`，
> 並在 `format_report()` 印出置換次數、p 值下限，以及
> **下限與通過門檻太接近時的紅字警示**。
> 回傳的 dict 也多了 `p_floor` 欄位供下游使用。
>
> ⚠️ **置換次數本身仍是 200**（`run_all` 的預設沒有動——那個檔案由別人
> 在改）。改的是**報告會誠實印出解析度**，讀的人看得到「這個 p 值只有
> 這麼細」。**口試／論文那一輪仍然要明確指定 `--ablation-permutations 1000`。**

### 現況（修正前）

```
d18_permutation_test.py:  DEFAULT_N_PERMUTATIONS = 1000
run_all.py --ablation-permutations 預設 200
```

`sklearn.permutation_test_score` 的 p 值是
`p = (C + 1) / (n_permutations + 1)`，其中 `C` 是置換分數 ≥ 真實分數的次數。

| 置換次數 | p 的最小可能值 |
|---|---|
| 200（`run_all` 預設） | **1/201 ≈ 0.00498** |
| 1000（`D18` 的預設） | 1/1001 ≈ 0.000999 |

### 委員會怎麼問

> 「你報 p < 0.01，那是真的 0.003 還是你的解析度就只到這裡？」

🔴 **用 200 次置換時，「p = 0.005」與「p 小到量不出來」在數值上長得一模一樣。**
而 `D18`/`D19` 的通過門檻正是 **p < 0.01**——**只差兩格**。

⚠️ **絕對不能宣稱 `p < 0.0001`**，那需要至少 9999 次置換。

### 為什麼是 200

那是我在 `D15` 設的，理由寫在 CLI 的 help 裡：完整 1000 次約需 70 秒，
會吃掉大半個「兩分鐘」的時間預算，而**跨實驗一致性檢查只需要它的方向、
不需要 p 值精度**。

**那個理由對「一致性檢查」成立，對「寫進論文的 p 值」不成立。**

### 最小修法提案（不動手）

1. **口試／論文用的那一輪一律 `--ablation-permutations 1000`**
   （CLI help 已經這樣寫了，但**報告本身沒有記錄用了幾次**——見下）
2. 🔴 **報告要印出實際用的置換次數與 p 值下限**。
   目前 `run_all` 的 `ExperimentOutcome` **沒有帶這個數字到 `summary.md`**，
   所以**讀報告的人看不出這份 p 值的解析度**。
   → 最小修法：`serialize_verify_report()` / `format_report()` 多印一行
   `n_permutations=N（p 下限 1/(N+1)）`。

## 3. ✅ 獨立性：同一個人的多筆錄音被當成獨立樣本 — **已修**

> **2026-08-26 修正**：`run_permutation_test()` / `permutation_report()`
> 新增選填的 `groups=`，有 ≥2 個 group 時改用 `StratifiedGroupKFold`。
>
> **實測（合成資料，刻意放入戴法洩漏訊號）**：
> 同一批資料，未分組準確率 **0.917**，按 `wear_id` 分組後 **0.625**。
> **那 0.29 就是被擠掉的水分。**
>
> 🔴 **只有一個 group 時（第一批資料很可能只戴一次）不會安靜退回舊行為**
> ——回傳 `grouping="ungrouped_single_group"`，報告明印
> 「**分組驗證無法進行**……結果可能被組內洩漏灌水」。
>
> ⚠️ **`run_all` 還沒有把 `wear_id` 傳下去**（那個檔案由別人在改）。
> 介面已經備好，接上去只要多傳一個參數。

### 現況（修正前）

```python
cv_splitter = StratifiedKFold(n_splits=cv, shuffle=True, random_state=random_state)
```

`StratifiedKFold` **只按類別分層，不按受試者或戴法分組**。

而 `permutation_test_score` 打亂的是**標籤**（正確的虛無假設：
「特徵不攜帶詞彙資訊」），但它**在打亂後仍用同一個 CV 切法**。

### 為什麼這是問題

`E05` 的資料是**同一個受試者、同一次戴上、連續錄很多筆**。
同一次戴上的兩筆錄音共享：戴法幾何、當下的環境光、感測器溫度、
甚至受試者當下的說話習慣。

🔴 **它們不是獨立樣本。** 隨機切 CV 會把同一次戴上的樣本
**同時放進訓練集與測試集**——模型可以靠「認出這是哪一次戴上」而不是
「認出這個詞」來得分，而**那個得分會通過置換檢定**（因為置換打亂標籤時，
那個洩漏也一起被打亂了……但只在標籤與戴法無關時成立，
而 `E05` 若是「一次戴上錄完一組詞」，兩者就**相關**了）。

### 委員會怎麼問

> 「你的交叉驗證有沒有按受試者/session 分組？同一次錄音的資料會不會
> 同時出現在訓練和測試裡？」

**這是機器學習審查最標準的一問**，而目前的答案是「沒有分組」。

### 但也要講清楚嚴重程度

* **只有一個受試者**時，「按受試者分組」無從做起——這是**單受試者研究**的
  固有限制，誠實寫出來即可（`HANDOFF.md` 已有「本系統不涵蓋舌音」那類
  誠實限制的先例）。
* **真正可做的是按 `wear_id` 分組**：`GroupKFold(groups=wear_id)` 或
  `StratifiedGroupKFold`。`E04` 要錄 20 次戴脫，**資料結構上是有 group 的**。

### 最小修法提案（不動手）

`run_permutation_test()` 加一個選填的 `groups=` 參數，有值時改用
`StratifiedGroupKFold`。**上游 `Trial.wear_id` 已經有了**
（`analysis/reporting/session_loader.py`），只是沒有傳下去。

⚠️ **改了以後準確率會掉，而那是對的**——現在的數字可能被戴法洩漏灌水。
**在 `E05` 的真實資料到手前先改，比拿到數字之後再改好**，
否則會變成「因為數字難看所以改方法」。

| `C` Silhouette | `0.5 / 0.3 / 0.15` | 註解與 `D13.md` 都寫「**照簡報**」 | ❌ 簡報不是實測也不是文獻 |

### 委員會怎麼問

> 「2 mm 這個門檻是怎麼來的？為什麼不是 1 mm 或 5 mm？」
> 「Silhouette 0.15 這個界線的依據是什麼？」

🔴 **三個都答不出來。** 而且它們是**必通過**閘門——
`summary.md` 裡寫著「這幾項是下游所有數字的前提」。

### 這件事已經有先例

`config/quality_thresholds.json` 對每個門檻都標了 `[契約]` 或 `[暫定]`，
`_source` 欄位寫明出處，並註明「實測後應該回頭調整」。
**`MUST_PASS` 的三個門檻沒有這個待遇。**

### 最小修法提案（不動手）

1. **在三個常數旁邊補 `_source` 註解**，照 `quality_thresholds.json` 的格式，
   標成 `[暫定]` 並寫明「待 `E01`–`E03` 實測校準」
2. **報告裡的通過矩陣加一欄或一句**：說明這三個門檻是暫定值
   ——⚠️ **現在報告寫的是「這幾項是下游所有數字的前提」，
   讀起來像它們有權威性。**
3. `A` 的 SNR = 3 那個循環引用**要講出來**：
   它是**流程觸發點**（「低於它就換戴法」），拿來當**統計判準**是借用，
   兩者不是同一件事。

## 5. 🟠 沒有效果量、沒有信賴區間

### 效果量：完全沒有

`grep -rn "cohen\|effect_size" analysis/` → **零筆**。

**但不是完全沒東西**——報告裡有這些**本身就是效果量**的數字：

| 已有 | 是效果量嗎 |
|---|---|
| Silhouette 分數（`D13`） | ✅ **是**，而且是標準化的（−1 ~ 1） |
| `D19` 的 `dual_matrix_gain` / `mel_gain`（準確率差） | ✅ 是（未標準化） |
| `D14` 的 `excess_mean`（超出機率地板幾個 σ） | ✅ 是 |
| `D16` 的互信息（bits） | ✅ 是 |

🔴 **缺的是「配對比較」的效果量**：例如「ToF 比 Mel 好多少」現在只有
一個準確率差（`tof_gain`），**沒有標準化、沒有變異數資訊**。

### 委員會怎麼問

> 「這個差異有多大？0.03 的準確率差在你的樣本數下代表什麼？」

⚠️ **只給 p 值的話，樣本一多什麼都會顯著。** 目前 `E05` 樣本少，
問題反而相反（**檢定力不足**）——但兩個方向委員都會問。

### 信賴區間：`analysis/` 完全沒有，但前端有

🔴 **這是一個尷尬的不對稱**：

```
vl53l7cx_test/monitor/panel/js/modes/quiz.js:595
  // Wilson score interval, not the normal approximation
```

**`C21` 的前端統計列用了 Wilson score interval（正確做法），
而產出論文報告的 `analysis/` 一個 CI 都沒有。**

委員如果先看 Demo 再看報告，會發現**Demo 比報告嚴謹**。

### 最小修法提案（不動手）

1. **準確率一律附 Wilson CI**——`quiz.js:602` 的 `wilsonInterval(k, n)`
   十行不到，移植到 Python 沒有難度。⚠️ **不要用常態近似**，
   `C21` 當初就是為此特地選了 Wilson。
2. **Silhouette 已經是效果量**，只要在報告裡**明說它是**，
   不要讓它跟 p 值混在一起被讀成「顯著性」。
3. **配對比較補一個標準化效果量**（例如 Cohen's d on CV fold scores）。

## 7. 委員最可能問的五個問題與現在的答案

| 問題 | 現在答得出來嗎 |
|---|---|
| 「你做了幾個檢定？有校正嗎？」 | ❌ **答不出來** — 見第 1 節 |
| 「p < 0.01 的解析度是多少？」 | ❌ **答不出來**，而且報告沒印置換次數 — 第 2 節 |
| 「CV 有按 session 分組嗎？」 | ❌ **沒有** — 第 3 節 |
| 「這個門檻怎麼訂的？」 | ❌ **三個必通過門檻都答不出來** — 第 4 節 |
| 「這個差異有多大？」 | ⚠️ **部分**（有 Silhouette、增益，但沒有 CI 也沒有標準化效果量） — 第 5 節 |

### 一個可以主動出擊的點

**`D15` 的跨實驗一致性檢查是這份報告最強的方法學特色**，而且**沒有人會想到要問**：

> 六個實驗從不同角度量同一件事，**它們對得上才可信**。
> `D13` 說互補、`D16` 說增益為負、`D19` 說消融沒差——**三者矛盾時報告會攤出來**。

**這比任何單一 p 值都難反駁**，因為它不依賴任何一個檢定的假設。
建議在口試時**主動講**，而不是等著被問。

## 8. 優先順序（如果只能做兩件事）

1. 🔴 **置換次數 1000 + 報告印出置換次數**（第 2 節）
   ——**最便宜、最直接堵住一個致命追問**。改一個 CLI 參數 + 印一行字。
2. 🔴 **宣告單一主要假設，其餘標 exploratory**（第 1 節方案 A）
   ——**零計算改動**，只加一段文字，但它同時解決了多重比較的問題。

第 3 節（分組 CV）技術上最正確，但**它會讓數字變難看**，
所以**必須在 `E05` 資料到手之前決定**——否則就會變成
「因為數字難看所以改方法」，那比原本的問題更難解釋。
