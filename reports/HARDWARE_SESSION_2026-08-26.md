## 2. 🔴 USB 連線不穩定 —— 這是目前最大的阻礙

### 實測的斷線時間軸

背景監測程式每 5 秒查一次 `/device/status`：

```
12:51:20  🔴 掉線（穩定 0 秒）
12:52:55  🟢 恢復（斷了 95 秒）
12:53:20  🔴 掉線（穩定 25 秒）
12:57:25  🟢 恢復（斷了 245 秒）
13:05:10  🔴 掉線（穩定 465 秒 ≈ 7.7 分鐘）  ← 最久的一次
13:22     仍未恢復（已 17 分鐘）
```

**穩定時間：0 秒 / 25 秒 / 7.7 分鐘。**
**斷線時間遞增：95 秒 → 245 秒 → 17 分鐘以上。**

### 🔴 關鍵證據：不是感測器問題，是 USB 實體層

```
斷線期間：ls /dev/ttyUSB0  →  No such file or directory
```

**`/dev/ttyUSB0` 這個裝置節點整個消失再出現。**

而且斷線時**五條串流全停**（`tof_A`/`tof_B`/`mic`/`mel`/`heartbeat`）
——**連心跳都停**，代表整塊板子失去連線，不是某顆感測器掛掉。

⚠️ **一開始誤判成「感測器接觸不良」**，因為第一次觀察到的是
「只有 ToF 停、麥克風正常」。**後來才發現那是同一個問題的較早期表現**
（bridge 判定 `mic` 逾時比 `tof` 晚，因為 `mic` 的門檻計時起點不同）。

### 建議排查順序（由快到慢）

1. **換一條 USB 線** —— 線材內部斷裂從外觀看不出來
2. **換電腦上的 USB 孔**，不要用 hub
3. **檢查板子上的 USB 座** —— 鬆動、虛焊
4. 供電不足（兩顆 ToF 同時工作耗電不小）

### ✅ 這個問題是被「串流逾時偵測」抓到的

那個功能是同一天早上做的，**這是它第一次在真板子上派上用場**。

🔴 **沒有它的話**，畫面會顯示 `sensors_seen = "AB"`（兩顆都在）
——因為那個欄位記的是「**這條連線曾經看過誰**」，**不是「現在還有沒有」**。

**掉幀計數也不會動**（韌體端 `check_data_ready()` 失敗時，
累加計數器的整個區塊被跳過），**`$H` 上看起來跟完全正常一模一樣。**

## 3. 🔴 骨傳導麥克風：收不到聲音

### 三種測法，全部在雜訊等級

| 情境 | 安靜 RMS | 說話 RMS | 倍數 |
|---|---|---|---|
| **貼著（正常戴）** | 7 | 11 | **1.6×** |
| **用力壓緊皮膚** | 23 | 25 | **1.1×** |
| **拿開、對著大聲說話** | 10 | 14 | **1.4×** |

**一個正常的麥克風，對著大聲說話應該要 10 倍以上。**

### 這排除了什麼

- ❌ **不是「沒貼緊」** —— 壓緊反而更差（1.1×）
- ❌ **不是「用法錯誤」** —— 當一般麥克風用也只有 1.4×
- ✅ **麥克風是活的** —— 壓它的時候底噪從 7 升到 23，
  **它對機械擾動有反應，但對聲音沒有**

### 背景底噪本身是正常的

**安靜時 RMS 4–7**，佔滿刻度（32767）的 **0.015%**，約 **−76 dBFS**。

⚠️ 同一天查過韌體確認**這個數字本身沒問題**：
- I2S PDM RX 直接 16-bit，跟 `$M` 印的 `int16_t` 對齊，**沒有截斷**
- 唯一的濾波是一階 DC blocker，**不削弱交流訊號**
- RMS 直接對原始 PCM 算，**單位就是滿刻度 ±32767**
- **全韌體找不到任何 gain 常數**

**所以「很小」是真的收到這麼小，不是軟體壓掉的。**

### 待查方向（由易到難）

1. **麥克風開口被擋住？** PDM 麥克風的進音孔很小，被膠帶／外殼／泡棉蓋住就收不到
2. **資料腳位接錯？** 時脈線通了（所以有底噪），但資料線可能沒接對
3. **焊接不良或膜片損壞**
4. **型號不符** —— 例如實際是類比麥克風但韌體用 PDM

⚠️ **韌體端的腳位設定尚未跟實際接線核對過。** 那是下一步。

## 4. 🔴 一個門檻確定是錯的

```
config/quality_thresholds.json   noise_floor.green = 300
真板子實測安靜時                  RMS 4–7
```

**那個 300 精確對應 `mock_device.py` 靜音時的合成 RMS，不是量真麥克風訂的。**

→ **這個門檻在真實硬體上永遠不會跳**，等於沒在保護。

⚠️ **但目前不能改**，因為「說話時應該是多少」這個數字還沒有
——麥克風修好之前量不到。

## 5. 三個未驗證假設的現況

| 假設 | 狀態 |
|---|---|
| **`$H` 早於 `$STATUS`** | ✅ **已驗證成立**（`uart_cmd.c:256-257` 寫死順序，真板子上也確認） |
| **`dim` 是 zone 數不是邊長** | ✅ **已驗證**：`res=4`、`$T` 的 `dim=16`、值有 32 個 = 2×16 |
| **zone 排列是 row-major** | 🔴 **仍未驗證** —— 遮擋測試沒做成（背景太近，看不出變化） |
| **左邊是 A、右邊是 B** | 🔴 **仍未驗證** |

### 遮擋測試為什麼沒做成

第一次嘗試時感測器對著很近的東西（16–53 mm），**手指遮上去跟背景距離差不多**，
最大變化只有 4 mm（雜訊等級）。

**正確做法**（下次用）：
1. **先讓感測器朝向空曠處**，確認大部分格子是 `-1`
2. **再用單一手指靠近一個角落，3–5 公分**
3. 該格會**從 `-1` 變成一個小數字** —— ⚠️ **方向跟直覺相反：是「從無效變有效」**
4. **四個角落都做**，才分得出旋轉與鏡像

⚠️ **不要看面板的熱力圖判斷** —— 面板本身就是照 row-major 假設畫的，
**那是循環論證**。要看 `$T` 那一行的原始數字。
