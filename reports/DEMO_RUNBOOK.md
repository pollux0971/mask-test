## 🔴 在讀任何一步之前：現在整套 Demo 完全跑不起來

**這件事比任何一步的細節都重要，必須先講。**

實測（讀 `vl53l7cx_test/monitor/bridge_server.py` 全文，`grep recognize`
零筆結果；`grep -rn "RecognitionService("` 全 repo 只有它自己的測試檔
會建立這個物件）：

- **`POST /recognize`（四步 Demo 腳本的每一步都要靠它）沒有接進
  `bridge_server.py`。** 現在按下「觸發辨識」，`quiz.js` 會收到 404，
  畫面顯示「尚未串接（/recognize 還沒上線）」——這不是猜測，是
  `quiz.js` 自己的錯誤處理程式碼寫死的文字。
- **`GET /templates`（載入 `E06` 錄好的樣板）也沒有接。**
- **自動觸發（講話自動判斷該錄了）也沒有接**——`{type:"trial"}` 事件
  從來沒有任何東西發布過，所以就算 `/recognize` 接上了，也還是要靠
  手動按「觸發辨識」，不會是「你一開口系統就自動反應」。

**這是目前排在所有 Demo 細節之前的頭號問題，不是 Demo 當天才會遇到的
風險。** 下面每一步都是「假設 `/recognize`／`/templates` 已經接上」
寫的操作手冊——**在真的接上之前，這份手冊沒有辦法真的照著做**。
接上進度回報給調度員（`esp-mask-test-ed` 負責 HTTP wiring），這裡持續
追蹤。

## 第 0 步：開機——直接面對三個沒驗證過的假設

**這一步在證明什麼**：確認機器基本能動，以及「板子今天的表現，跟開發時
猜測的假設是不是一致」。**板子從來沒有燒過韌體**，所以這是全部假設
第一次接受檢驗的時刻，不是排練過的固定流程。

完整推導見 `reports/ASSUMPTION_RISK.md`，這裡只列「一分鐘判別法」：

| 假設 | 一分鐘判別法 | 錯了會怎樣（詳見 `ASSUMPTION_RISK.md`） |
|---|---|---|
| zone 排列是 row-major | 遮住感測器一個角落，看 signal 熱力圖哪一格變化 | 準確率不受影響，但熱力圖/D11 的方向解讀會左右或上下顛倒 |
| 左邊感測器是 A、右邊是 B | `SENS:B=0` 後用手機相機看哪顆近紅外光熄滅 | 準確率不受影響，只有 `D12` 報告的「左側/右側」標籤可能反過來 |
| `$H` 之後緊跟 `$STATUS` | 跑一次 PING burst，看回傳 JSON 的 `confirmed`／`meets_acceptance` 欄位，不要只看 RTT 數字本身 | `confirmed=False` 時 RTT 數字可能污染但看起來正常，見 `ASSUMPTION_RISK.md`「假設3」 |

**這一步最可能怎麼壞，當場怎麼救**：三個假設都「不會讓任何東西報錯」——
最危險的壞法是「看起來一切正常，但方向反了」。當場沒有時間重新驗證，
**能做的只有：先做上面三個一分鐘判別法，如果任何一個異常，口頭承認
「這項還沒驗證」，不要臨場編一個解釋。**

**哪些是真的、哪些是假設**：這三項全部是**未驗證的假設**，不是量過的
數字。誠實說「這是開發時的假設，今天是第一次在真機上檢驗」是準確的
說法。

## 第 1 步：`w = 0.5`，念「五」→ 三軌都對

**這一步在證明什麼**：系統的基本辨識能力——融合模式下，正常說話能被
正確認出來。

1. **操作**：確認測驗模式（側欄 `3`）的融合權重滑桿在中間（`w = 0.50`，
   或按鍵盤 `F`）。用正常音量念「五」，按「觸發辨識」（或等自動觸發，
   若當天已接上——見上方頭號問題）。
2. **畫面應該出現什麼**：三欄長條圖（ToF only／Mel only／Fused ★）
   的第一名都亮成「五」，最上面的大字結果卡顯示「五」，信心度環接近
   滿格，沒有「⚠ 三軌判斷不一致」的紅色橫幅。
3. **背後的程式路徑**：`quiz.js` 的 `onRecognizeClick()` → `POST
   /recognize` → `RecognitionService.recognize()`（`analysis/similarity
   /recognition_service.py`，`dist_method="cosine"`，`D22` 的雙邊 ROC
   拒識校準）→ 回傳 `TriResult` → `renderResult()` 畫三欄長條圖 +
   `updateResultCard()` 畫結果卡。
4. **最可能怎麼壞，當場怎麼救**：
   - 若三軌判斷不一致（紅色橫幅跳出來）：換一次「重試」按鈕，環境
     雜訊或戴法瞬間偏移都可能只影響一次。連續兩次都不一致才是真的
     問題。
   - 若整個沒反應／顯示「尚未串接」：見上方頭號問題，這代表
     `/recognize` 還沒接上，**不是這一步操作錯誤**。
   - 若辨識成別的詞：檢查是不是戴法跑掉（看熱力圖對稱性指標），
     不要重錄樣板當場賭一把。
5. **哪些是真的、哪些是合成**：**目前全部合成**——`analysis/similarity
   /test_recognition_service.py` 用合成資料證明辨識邏輯本身正確，
   但沒有一筆真實錄音跑過這條路徑。真實表現要看 `E06` 的 LOOCV
   （目前 `E06.md` 裡的 85%/78%/45% 是**故事文件裡的範例目標數字，
   不是量過的結果**——`E06` 需要硬體，還沒有人做過）。

## 第 2 步：滑桿推到 `w = 1.0`（純 ToF）→ 再念「五」→ 仍然對

**這一步在證明什麼**：辨識不是只靠聲音——把音訊的權重整個關掉，
ToF 自己也認得出同一個詞。

1. **操作**：把滑桿推到最右（純 ToF），或按鍵盤 `T`。**不用重新念**
   ——`C17`/`D07` 的既有性質是同一個 `TriResult` 換 `w` 重算，**不會
   重新呼叫 `/recognize`**，這件事本身也值得口頭點出來（「拖著滑桿的
   時候，系統沒有重新錄音，只是換一種方式解讀同一份資料」）。如果
   想要更乾淨的展示效果，也可以先推滑桿再念一次。
2. **畫面應該出現什麼**：Fused 欄變成跟 ToF only 欄一模一樣（因為
   `w=1` 時 `fuse(1) = d_tof`），大字結果卡維持顯示「五」，`w` 數值
   讀出變成 `w = 1.00`。
3. **背後的程式路徑**：`quiz.js` 的 `onSliderInput()`/`setW()` →
   `renderFusedColumn()`（純前端重算，`fuseScores(lastTriResult, 1)`），
   完全不打 API。
4. **最可能怎麼壞，當場怎麼救**：
   - **若這裡認不出來**：對照 `E06.md` 的提醒——「如果 ToF-only 接近
     隨機基準 12.5%，這步 Demo 做不成」。當場救法：**誠實改口**，
     改成第 3 步先做（silent 模式的獨立價值），跳過這步的「仍然對」
     論述，不要硬撐。
   - 拖滑桿沒有網路延遲問題（前端算的），若卡頓多半是瀏覽器本身效能
     問題，見 `reports/PANEL_INTEGRATION.md`/`C_monitor_perf.md`
     （`monitor` 模式才是已知的 CPU 大戶，測驗模式不是）。
5. **哪些是真的、哪些是合成**：`D07`（`w` 換算不重打 API）跟 `D22`
   （拒識在 `w=1` 時退化成 `reject_tof`）**這兩個性質本身**已經用合成
   資料的 pytest 釘住（`recognition_service.py` 的
   `test_w_change_does_not_recompute_distances`）。**但「ToF-only 真的
   認得出『五』」這件事——沒有真實數字**，同第 1 步。

## 第 3 步：氣音／無聲念「五」→ Mel 軌崩潰、ToF 軌仍對

⚠️ **這一步的用詞在 story 跟實際介面之間有落差，Demo 前必須先決定**：
`E07.md` 寫「用氣音念『五』（silent）」，把「氣音」跟「silent」當同一件
事講。但 `quiz.js` 的說話模式其實是**三個獨立按鈕**：「正常」／
**「氣音」（whisper）**／**「無聲」（silent）**，行為不一樣——「無聲」
模式下 Auto-VAD 的偵測器整個換掉（`B13.md`：無聲模式沒辦法用聲音判斷
起訖，UI 會改顯示「Auto-VAD 不適用（無聲模式）」並要求手動選觸發來源）。
**Demo 前要先決定「氣音」（有聲音但很小聲）還是「無聲」（完全不出聲、
純嘴型）才是真正要展示的動作**，這裡沒有幫忙決定——兩種都能讓 Mel
軌失效，但介面上是兩個不同的按鈕，說詞要跟按的按鈕對上。

1. **操作**：按「氣音」或「無聲」（依上面先決定的那個），用選定的方式
   念「五」，按「觸發辨識」。
2. **畫面應該出現什麼**：Mel only 欄顯示「拒識」badge 且該欄暗色，
   ToF only 欄跟 Fused 欄仍然顯示「五」，「⚠ 三軌判斷不一致」的紅色
   橫幅**應該**跳出來（因為 Mel 拒識、其他兩軌有答案，見下一點的
   重要細節）。
3. **背後的程式路徑**：`updateDisagreement()`——**拒識不是分歧，是
   沉默**這條原則（`CONTRACTS.md`，C16 review 後訂的）：Mel 拒識時不
   會被當成第三個意見去跟其他兩軌比較，只比較「有給出答案的那幾軌」
   彼此吻不吻合。**所以如果只有 Mel 拒識、ToF 跟 Fused 都答「五」，
   横幅不會跳出來**（因為只剩兩個有意見的軌，而且它們一致）——這是
   正確行為，**不是 bug**，但上台前務必先弄清楚這一點，不要被問到時
   反應不過來。
4. **最可能怎麼壞，當場怎麼救**：
   - 若 Mel 軌沒有拒識、還是給出答案：代表氣音/無聲不夠安靜，或麥克風
     沒有正確反映音量差異。當場救法：加大氣音/無聲的程度再試一次；
     若還是不行，**這步的論證改成口頭講**（「這裡示範的是機制設計，
     完整的 silent-mode 驗證要等真實資料集」）。
   - 若無聲模式下整個 ToF 軌也連帶失效：檢查觸發來源是不是被切到
     「僅音訊」，`B13.md` 規定無聲模式要能選 ToF 或任一觸發來源。
5. **哪些是真的、哪些是合成**：**拒識判定的機制**（`reject_mel`
   計算、`updateDisagreement()` 的「拒識不是分歧」邏輯）是合成資料
   pytest 釘住的既有邏輯，**機制本身可信**。**Mel 軌在真實氣音/無聲
   下真的會拒識**——沒有真實資料驗證過，這是全場**唯一需要真人在
   台上真的示範才能知道會不會發生**的一步，排練的價值在這裡最高，
   但 `E07`（排練）已經被使用者跳過。**這代表這一步上台前完全沒有
   被驗證過會不會成功。**

## 第 4 步：純 ToF 念「四」→ 認不出來

⚠️ **`esp-mask-test-7c` 正在驗證這條路徑，可能會找到問題。這裡先寫
現況，等它的結果調度員會轉過來補。**

**這一步在證明什麼**：主動示範一次失敗，把「ToF 的能力邊界」講清楚，
反而提升整場的可信度（`E07.md` 原文：「委員最怕的是看到一個永遠成功
的 Demo」）。

1. **操作**：滑桿維持在 `w=1.0`（純 ToF，延續第 2 步），念「四」，
   按「觸發辨識」。
2. **畫面應該出現什麼**：ToF only 欄與 Fused 欄都顯示「拒識」badge，
   結果卡改成虛線邊框顯示「未偵測到」（`C18.md`：這個狀態要跟正常
   結果同樣大方，不是縮小或變暗的卡片）。
3. **背後的程式路徑**：`computeFusedReject()`（`theta_reject_fused(w)
   = w*theta_reject_tof + (1-w)*theta_reject_mel`，`w=1` 時退化成
   `theta_reject_tof`，用的是 `d_tof_raw`／`d_mel_raw`——**必須是未
   正規化的原始距離**，這是 C-track 早期一次「差點做錯」的細節，見
   `ssi-backlog/CONTRACTS.md` §4.3 的變更紀錄）。
4. **最可能怎麼壞，當場怎麼救**：
   - **最大的風險是反過來：ToF 反而認得出「四」**。這樣第 4 步的
     論述會整個垮掉。當場救法：**改口**，把第 4 步從「示範失敗」
     改成「這兩個詞剛好都在 ToF 的可分辨範圍內，但通用地說 ToF-only
     的準確率是 X%（`E06` 的數字，如果有）」，不要現場硬拗成一次
     巧合的成功。
   - 若整個沒反應（沒有拒識也沒有答案）：檢查是不是又是頭號問題
     （`/recognize` 沒接上），不是 ToF 真的判斷了什麼。
5. **哪些是真的、哪些是合成**：`computeFusedReject()` 在 `w=1` 時退化
   成 `reject_tof` 這個**性質**是合成資料 pytest 釘住的（`recognition
   _service.py` 的 `test_reject_tof_still_works_at_w1_after_full_service
   _wiring`，用低維度合成資料統計驗證，不是斷言單一樣本）。**「四」
   真的會被拒識、「五」真的不會**——這是這場 Demo 裡**唯一目前有人
   在專門查證**的一步，其他都還沒人碰，狀態最新，等 `7c` 的結果。
