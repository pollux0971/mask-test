# D13 — Silhouette 分數為什麼會「莫名其妙」偏低：維度詛咒筆記

給 `E05` 之後真的拿真實資料跑 `analysis/experiments/exp_c_silhouette.py` 的人看。
如果分數普遍偏低，**第一反應不該是「模型爛」或「資料爛」**，先看這篇。

## 開發時實際踩到的坑

`exp_c_silhouette.py` 開發階段用合成資料測試（見
`analysis/experiments/test_exp_c_silhouette.py` 的整合測試）。第一版合成
資料只讓**單一** zone（ToF）或**單一** band（Mel）帶詞彙訊號，其餘通道
純噪音——這是模擬「感測器只有一小塊區域對某個詞有反應」的直覺寫法。

結果：六種組合的 Silhouette 分數全部卡在 **0.05–0.08**，判定一律 `fail`。

把合成資料改成「多個 zone / 多個 band 上一致的固定 pattern」（更接近真實
唇形或頻譜會同時牽動多個通道的物理直覺）之後，**同一套 `exp_c_silhouette.py`
程式碼、同樣的判定門檻**，ToF 三種 mode 都拿到 **0.75–0.78**（強分離）。

程式邏輯完全沒有改變。改變的只有訊號在特徵向量裡的分散程度。

## 為什麼會這樣：機制

1. `stack_modality()` 把 `(T=24, D)` 的特徵序列攤平成一條 `T*D` 維的向量
   （例如 `tof_combined` 是 24*64=1536 維，`all` 是 24*104=2496 維）。
2. `silhouette_for_modality()` 對這批攤平向量做 `StandardScaler`——**每一維
   都被獨立正規化成零均值、單位變異數**，不管這一維原本帶不帶詞彙資訊。
3. 如果詞彙訊號其實只集中在少數幾個 zone/band，攤平後這些「有訊號的維度」
   只佔總維度數的一小部分，其餘幾百維是跟標籤完全無關的純噪音。
   StandardScaler 把它們拉到跟訊號維度同樣的變異數量級之後，這些噪音維度
   在總變異量裡的佔比反而被「拉平」到跟訊號維度差不多。
4. `PCA(n_components<=50)` 想在這種高維、大部分維度是噪音的情況下找出
   「有結構的子空間」，但**樣本數遠小於維度數**時（例如 D13 自己的測試只
   用 24-40 筆 trial，維度卻有上千），PCA 的前幾個主成分不保證對齊到那一小
   塊真正有訊號的子空間——它們同樣容易被大量噪音維度之間的隨機相關性
   主導。這正是 `n_pca_components=50` 這個參數想緩解、但**不保證解決**的
   維度詛咒本身（story 原文也提到「PCA 降到 50 維是為了讓歐氏距離在高維
   下仍有意義」——是「為了」，不是「保證」）。

## 排查順序（建議）

真實資料分數普遍偏低時，依序檢查，不要跳過第 1、2 步直接懷疑資料品質：

1. **訊號是不是集中在少數幾個通道？** 看 `D01` 的 `active_zone_indices()`
   輸出——如果只有 1-2 個 zone 通過 SNR 門檻，攤平+PCA 這條路線本來就
   會稀釋掉這個訊號，不代表 ToF 沒有資訊。
2. **樣本數夠不夠撐 PCA(50)？** `silhouette_for_modality()` 回傳值裡的
   `n_components` 會告訴你實際用了幾維（被夾在
   `min(50, n_samples-1, n_features)`）。如果 `n_components` 遠小於 50
   （例如每詞只錄 5-10 次、8 個詞，n_samples 大概 40-80），PCA 本身就
   沒有多少自由度可以分離噪音與訊號。
3. **考慮不攤平、改用能感知結構的距離量測。** 如果 1、2 都排除了還是低分，
   才需要懷疑資料本身或特徵計算——這時候可以考慮 D05 的 DTW（沿時間軸
   對齊，不是整段攤平比歐氏距離）作為交叉驗證，而不是繼續調 D13 的參數。

## 這跟 D18（Permutation Test）的關係

D13 的 Silhouette 分數本身不會告訴你「這個分數是不是隨機也能達到」。
`D18` 用打亂標籤重跑 N 次建立 null distribution，能回答「真實分數跟隨機
分數比起來顯著嗎」——這是 D13 分數的必要補充，不是重複勞動。分數偏低
時，D18 的 null distribution 也能幫忙判斷：如果連隨機打亂標籤都能拿到
差不多的分數，那就不是維度詛咒的問題，是真的沒有可分性。
